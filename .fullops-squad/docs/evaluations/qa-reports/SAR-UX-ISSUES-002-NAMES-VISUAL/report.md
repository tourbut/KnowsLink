### 현행 유지로 판정한 표시

- `.name-preview`(2줄 말줄임)가 내 에이전트 카드 제목과 친구 목록 이름에 적용된다. 320·390에서 40자 이름이 ‘…’로 끝난다(`T/chrome-agents-a-320.png`, `T/chrome-friends-c-after-390.png`). 바로 아래에 구분값 줄이 있고 전체 이름은 상세·친구 상세에 있다. 현행 유지한다. tester의 `ell` 검사는 `-webkit-line-clamp`를 잡지 않으므로 ‘말줄임 없음’은 이 두 곳에는 맞지 않는다.
- 헤더의 ‘내 계정’ 표시는 U7의 ‘설정’ 이름 변경 전이다. U3(5단위)에서 처리한다.

## 제품 결정

### 결정 1 (O-NM-01) 요청자에게 ‘거절’을 보인다 — 현행 유지 + 안내 한 줄

- 결정: 받은 사람이 거절하면 요청자 기록에 ‘거절’을 계속 보인다. HP-04 상태 구분과 U4 ‘종료별 의미를 합치지 않는다’를 따른다.
- 근거: U4 비노출 규칙의 대상은 제출 시점의 자동 존재 확인이다. 거절은 받은 사람의 명시적 행동이다. 코드는 길고 무작위이며 당사자가 직접 건넨 값이라 거절 표시가 대량 존재 확인 수단이 되지 않는다. 받은 사람에게는 알리지 않는 선택(응답하지 않고 기한 만료)이 이미 있다. 만료는 없는 코드와 같은 모양이므로 비노출이 유지된다.
- DEV 구현 기준: 받은 요청의 ‘거절’ 버튼 앞 muted 문장에 ‘거절하면 요청한 사람의 기록에 거절로 표시됩니다. 알리지 않으려면 응답하지 않아도 기한이 지나면 요청이 끝납니다.’를 둔다. 요청자 화면, 상태 값, 거절 버튼 동작은 바꾸지 않는다.
- 유지할 경계: 응답 없는 만료와 없는 코드의 만료는 요청자에게 같은 ‘만료’다. 차단 여부는 요청자에게 보이지 않는다(HP-14).

### 결정 2 (O-NM-02) 새 대화의 발신·수신 선택기는 radio로 바꾼다

- 결정: ‘내 발신 에이전트’와 ‘<상대>의 수신 에이전트’(자기 대화는 ‘내 수신 에이전트’)를 조회 화면과 같은 fieldset/legend + radio로 바꾼다. 라벨은 `이름 / 종류 / 구분값`이며 줄바꿈해 전부 보인다. 구분값이 충돌하면 조회와 같은 규칙으로 늘린다.
- 근거: 닫힌 select는 좁은 폭에서 이름 뒤의 구분값을 숨긴다. 동명 발신·수신을 구별하지 못하면 잘못된 에이전트로 대화를 열 수 있다. radio 라벨은 1단위에서 이미 3폭·키보드·44px 검증을 통과했다. 구분값 선두 select 예외(세션 선택기)보다 같은 패턴 재사용이 일관적이다.
- 기본 선택: 현재 select의 기본 선택 동작을 유지한다. 선택지가 바뀌는 다른 규칙은 이번 범위에 넣지 않는다. 대화 열기 실패 뒤 선택 보존은 기존 계약을 유지한다.
- 수락 기준: 390·320에서 39자 동명 두 에이전트의 라벨이 서로 다른 구분값까지 보인다. 페이지 가로 넘침 0, 각 radio 라벨 44px 이상, 방향키로 선택, Enter로 제출.

### 결정 3 (D-NM-01) 이름의 금지 문자 거부 문구와 입력 복구

- 결정 문구(금지 문자): ‘이름에 줄바꿈·제어 문자·방향 제어 문자는 쓸 수 없습니다. 보이는 글자로 1–40자를 입력하세요.’
- 길이·빈 이름 오류는 현행 ‘이름은 1–40자로 입력하세요’를 유지한다. 두 조건이 함께 있으면 금지 문자 문구를 보인다.
- 입력 복구: 거부 뒤 입력란에는 금지 문자를 제거한 나머지 글자를 남긴다(조회 ID와 같은 방향). 제거 결과가 비면 빈 입력이다. 자동 저장하지 않는다. 사용자가 확인 후 다시 저장한다.
- 적용 범위: 에이전트 이름 저장, 에이전트 추가의 이름, 내 이름 저장. 같은 검증을 쓰는 모든 이름 입력에 같은 문구를 쓴다. 이름 불변·422·alert·`aria-invalid`는 유지한다.
