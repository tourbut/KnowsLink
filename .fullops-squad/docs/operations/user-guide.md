# KnowsLink 본인 전용 합성 베타 사용자설명서 (D11)

이 문서는 사용자 본인이 합성 데이터로 베타를 시험하는 방법이다. 서버는 `link.knowslog.com`이다. 접근은 사용자 본인 이메일 한 개로 제한한다. 실제 업무 데이터·실제 벤더·실제 일정은 입력하지 않는다.
공개 연결은 2026-10-03에 적용됐다. 미인증 요청은 모두 Cloudflare Access 로그인으로 이동한다. 마지막 이메일 로그인은 사용자가 직접 확인하는 인간 검사다. 현재 상태는 [D13](transition.md)에서 확인한다.

## 시험 절차

1. 서버 터미널에서 합성 시험 자료를 만든다.
   `/home/shin/deploy/knowslink/deploy/knowslink/beta.sh seed`
   기대: `UI candidate: http://127.0.0.1:8080/owner/gates/<id>`가 출력된다. 이 gate는 생성 후 180초에 만료된다.
2. 같은 터미널에서 로그인 값을 확인한다.
   `/home/shin/deploy/knowslink/deploy/knowslink/beta.sh owner-login`
   기대: `username`과 `basic-auth value`가 출력된다. 합성 값이다. 다른 곳에 붙여 넣지 않는다. 이 명령은 사용자 본인이 자기 터미널에서만 실행한다. agent에게 실행시키지 않는다.
3. 브라우저에서 `https://link.knowslog.com/owner/gates/<id>`를 연다. `<id>`는 1단계 출력에 있다.
4. Cloudflare Access 화면에서 본인 이메일을 입력한다. 이메일로 온 일회용 코드를 입력한다. 기대: 소유자 화면의 HTTP Basic 로그인 창이 나온다.
5. 브라우저 로그인 창의 사용자 이름 칸에 2단계의 `username` 값을 입력한다. 비밀번호 칸에 `basic-auth value` 값을 입력한다. 기대: pending gate 내용이 나온다.
6. Approve 또는 Deny를 누른다. 기대: 결정 결과 화면이 나온다. 페이지를 여는 GET 요청만으로는 결정되지 않는다.
7. 만료된 gate는 1단계를 다시 실행한다.

## 사용하지 않는 것

- 본인 이메일이 아닌 계정은 접근할 수 없다. Access가 차단한다.
- agent의 API 호출은 서버 안의 loopback(`127.0.0.1:8080`)에서만 실행한다. 공개 주소에서 API 자동 호출은 지원하지 않는다.
- 실제 정보 공개·벤더 효과·positive silent done은 꺼져 있다.

## 일반 이메일 가입과 로그인 (SAR-PUBLIC-IDENTITY-001 후보)

이 절은 일반 이메일 회원 화면의 사용 방법이다. 공개 주소에는 아직 적용되지 않았다. 공개 적용과 실제 이메일 확인은 OPS 배포·독립 검증 뒤 진행한다. 위의 본인 전용 베타 절차는 그대로 유지된다.

관리자 아이디·서버 접속(SSH)·HTTP Basic 값·별도 초대는 필요하지 않다. 이메일 하나만 있으면 된다.

### 가입·로그인

1. 서비스 주소의 첫 화면(`/`)을 연다. 기대: "이메일로 가입·로그인" 화면이 나온다.
2. 이메일 주소 하나를 입력하고 "확인 코드 받기"를 누른다. 기대: "확인 대기" 화면이 나온다. 이 화면은 아직 로그인 상태가 아니다.
3. 메일함에서 "KnowsLink 확인 코드" 메일의 6자리 코드를 확인한다. 코드는 10분 동안 한 번만 쓸 수 있다.
4. 코드를 입력하고 "확인하고 로그인"을 누른다. 기대: "내 KnowsLink" 홈 화면이 나온다.

처음 확인한 이메일은 새 회원이 된다. 같은 이메일로 다시 로그인하면 같은 회원과 같은 목록을 본다. 대문자와 소문자는 같은 주소로 처리한다. `+태그`가 붙은 주소는 다른 회원이다.

### 문제가 생겼을 때

| 화면 문구 | 의미 | 다음 동작 |
|---|---|---|
| 코드가 맞지 않습니다. 남은 시도: N회 | 오답이다 | 메일의 코드를 다시 확인한다. 5번 틀리면 새 코드를 받는다 |
| 확인 코드가 만료되었거나 더 이상 쓸 수 없습니다 | 10분 경과·5회 오답·이미 사용·새 코드 요청 | 첫 화면에서 새 코드를 요청한다 |
| 요청이 많습니다. 시각 이후 다시 시도하세요 | 같은 이메일 60초 간격·시간당 한도·접속 위치 한도 | 표시된 시각 뒤에 다시 시도한다 |
| 확인 메일을 보내지 못했습니다 | 메일 발송 실패. 로그인되지 않았다 | 1분 뒤 다시 요청한다. 계속 실패하면 운영자에게 알린다 |
| 현재 신규 가입을 받을 수 없습니다 | 회원 수용량 도달. 기존 회원은 로그인할 수 있다 | 나중에 다시 시도한다 |
| 세션이 끝났습니다 | 12시간 경과 또는 60분 무활동 | 다시 로그인한다 |

메일이 오지 않으면 스팸함을 확인한다. 화면은 가입 여부와 관계없이 같은 안내를 보인다.

### 홈 화면과 로그아웃

홈 화면은 가려진 이메일(예: `s***@example.com`)과 회원 식별자를 보인다. 지원 요청에는 회원 식별자만 알린다. 이메일 전문·확인 코드는 다른 사람이나 agent에게 알리지 않는다.

- "이 브라우저에서 로그아웃": 현재 브라우저만 로그아웃한다.
- "모든 브라우저에서 로그아웃": 최근 5분 안에 이메일을 확인했을 때만 누를 수 있다. 버튼 대신 "이메일 다시 확인"이 보이면 그 버튼으로 새 코드를 받아 확인한다.
- 로그아웃은 연결한 agent의 키와 자격을 철회하지 않는다.
- 계정 비활성화는 "준비 중"이다. 아직 요청할 수 없다.
- 공개 서버 `link.knowslog.com`에는 아래 후보 절차가 배포되어 있지 않다. 공개 시험은 이 문서 앞부분의 합성 베타 절차를 따른다.
- 승인 요청이 있으면 홈의 목록에서 열어 Approve 또는 Deny를 누른다. 페이지를 여는 것만으로는 결정되지 않는다.

## 후보 전용 agent 연결

이 절은 후보 `458798c2ee15c179edacfd6f94ebb9896d26f411`의 회원 화면이다. 공개 서버의 현재 절차가 아니다. 운영 수락은 아직 없다.

1. 홈에서 새 agent를 만든다. 활성 agent는 회원당 5개다. 5개를 넘기면 쓰지 않는 agent를 먼저 철회한다.
2. 연결은 Node 22가 있는 자기 컴퓨터의 로컬 클라이언트에서 한다. 개인키는 그 컴퓨터에만 둔다.
3. 상대 agent 식별자로 초대한다. 수신 owner가 수락하기 전에는 메시지를 보낼 수 없다. 같은 owner의 두 agent도 수락이 필요하다.
4. 이미 대기 중인 초대나 이미 연결된 관계를 다시 보내도 새 초대가 생기지 않는다. 기한도 바뀌지 않는다.
5. 거절, 만료, 또는 어느 쪽의 관계 철회 뒤에는 새 초대를 보낸다. 상대가 그 초대를 다시 수락해야 한다. 옛 수락은 다시 쓸 수 없다.
6. 철회한 agent는 최소 24시간 동안 목록에 남을 수 있다. 목록에서 사라져도 권한이 돌아오거나 백업이 영구 삭제된 것은 아니다. 정확한 삭제 시각은 약속하지 않는다.
7. 한 agent의 키 기록이 꽉 차면 그 agent에 새 키를 연결할 수 없다. 키를 철회하거나 기다려도 그 자리가 생기지 않는다. 새 agent를 만들고 상대와 다시 수락한다.
8. 철회 기록까지 꽉 차면 새 agent를 만들 수 없다. 최소 24시간이 지나 목록에서 정리된 뒤에 다시 만든다. 기존 자격은 그 거절만으로 지워지지 않는다. 철회는 여전히 할 수 있다.
9. 요청이 많으면 화면이 다시 시도할 시각을 보인다. 연결 API의 429는 `retry_at`과 `Retry-After`에 같은 시각을 담는다.
10. 계정 비활성화는 이 후보에서도 "준비 중"이다.
