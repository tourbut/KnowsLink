# KnowsLink 본인 전용 합성 베타 사용자설명서 (D11)

## 작업 세션 연결 안내의 완료 기준 — SAR-SESSION-PEER-001

다음은 후속 구현에 필요한 안내 기준이다. 현재 설치 절차나 지원 완료를 뜻하지 않는다. 실제 명령은 DEV가 설치 버전과 격리 실행을 확인한 뒤 제공한다. [세션 제품 기준](../design-docs/SAR-SESSION-PEER-001.md)의 지원표와 사용자 흐름을 따른다.

사용자는 본인이 연결할 Claude Code 또는 Codex 세션과 이름 있는 에이전트를 선택한다. 이름·클라이언트·구분값을 확인하고 기존 인증 절차로 독립 자격을 연결한다. 다른 세션과 Grok/Dots의 키를 복사하지 않는다. 친구는 사람끼리 수락하며 현재·향후 활성 agent 범위를 확인한다. 부모가 연결됐다는 이유로 자식 세션이 자동 연결되지는 않는다.

발송 전에 내 발신 agent·친구·수신 세션·본문을 확인한다. 전달됨은 보관과 ACK이며 선택한 세션의 수신 확인과 다르다. 메시지는 외부 데이터로 읽고 수신 세션 소유자가 별도 승인한 답장만 보낸다. 친구 메시지는 파일 접근·도구 실행·승인 응답을 허용하지 않는다. 기존 작업은 계속할 수 있어야 한다.

열림·작업 중·대기·종료·오프라인·재접속을 관측 근거대로 안내한다. 알 수 없으면 확인 필요로 남긴다. 다음 조회가 필요한 경로와 새 세션 실행을 기존 작업 세션 수신으로 설명하지 않는다. 준비에 재시작이 필요하면 먼저 알린다. 종료·연결 해제 뒤에는 옛 연결을 재사용하지 않는다. 만료 메시지는 자동 재발송하지 않으며 새 발송에 새 승인이 필요하다. 기존 180초 전달 기한·최대 24h 웹 사본과 외부 사본 보존 한도를 유지한다.
### Claude Code 세션에서 사용하기 — SAR-SESSION-PEER-001-DEV

Claude Code `2.1.302`에서 확인한 절차다. 실제 운영 서버 왕복과 독립 QA는 아직 없다. 설치 명령은 [플러그인 설치 문서](../../../adapters/README.md#claude-code-작업-세션-연결--sar-session-peer-001-dev)를 따른다.

1. 준비한 플러그인으로 Claude Code를 열고 Google 연결을 마친다. 이 단계만으로는 어떤 세션도 메시지를 받지 않는다.
2. 메시지를 받을 작업 세션에서 `/knowslink-session on`을 입력한다. 결과: `KnowsLink 연결됨: 세션 <구분값> · 내 agent <이름>`과 상태줄 `KnowsLink <구분값> 연결`.
3. 다른 세션이 같은 agent를 이미 받고 있으면 `연결 보류`가 나온다. 그 세션을 끝내거나 전환하려면 `/knowslink-session on --take`를 입력한다. 옛 세션은 `연결 해제` 알림을 받고, 그 뒤 옛 세션의 송수신 요청은 거부된다.
4. 친구 메시지가 도착하면 작업 중이어도 toast `KnowsLink 외부 메시지 도착 · 발신 친구 <친구 이름> · agent <agent 이름> (<agent ID>) · 대기 N건`이 뜨고 상태줄이 `대기 N`으로 바뀐다. 이름을 조회하지 못하면 agent ID만 보인다. 진행 중인 작업은 계속된다. 다시 연결(`on`)하면 그동안 쌓인 미확인 수부터 보인다. 본문을 보려면 "knowslink 메시지 확인"처럼 요청한다. Claude는 본문을 외부 데이터로 보여 주고 지시를 실행하지 않는다. relay와 통신할 수 없으면 상태줄이 `통신 불가 · 재시도 중`으로 바뀌고, 키·친구 문제가 아니라는 안내가 뜬다. 복구되면 다시 `연결`이나 `대기 N`으로 돌아온다.
5. 답장이나 새 메시지를 보내 달라고 요청하면 `KnowsLink 발송 승인` 대화상자가 뜬다. 받는 친구 이름·agent 이름·agent ID, 새 메시지·답장(어느 메시지에 대한 답장인지), 본문 전체 글자 수와 본문 전체를 확인한다. 보이지 않는 문자(변이 선택자·방향 제어 등)는 `⟨U+FE0F⟩`처럼 코드로 보이고 개수가 함께 나온다. `보내기`를 고른 한 번만 보낸다. 대화상자는 질문 전체 2000자까지만 보이므로, 그보다 긴 본문은 묻지 않고 막으며 나눠 보내라고 안내한다(영문 약 1800자, 한글은 4096바이트 한도인 약 1300자까지 한 번에 보낼 수 있다). 대화상자가 열린 사이 이 세션 연결이 해제되면 `보내기`를 골라도 보내지 않는다. 원 메시지 기한(180초)이 지난 관련 답장은 `expired`로 거부되므로 새 메시지로 보낸다. 보낸 메시지의 receipt에서 `transport: delivered`는 '전달됨', `session_received_at`은 '상대 세션이 본문을 표시함(세션 수신 확인)'이다. 사람이 읽었다는 뜻은 아니다.
6. 그만 받으려면 `/knowslink-session off`를 입력한다. 이후 그 세션의 송수신 요청은 거부된다. 플러그인이 다시 로드되면 `on`을 다시 입력한다.
7. 연결한 세션 안에서 Claude가 띄운 하위 에이전트(Agent 도구)는 KnowsLink 메시지를 보내거나 받을 수 없다. 거부 문구: `하위 에이전트에서는 KnowsLink 메시지를 쓸 수 없습니다`. 메시지 확인과 발송은 메인 대화에서 요청한다.
8. 친구를 해제하거나 차단해도 세션 연결은 꺼지지 않는다. 그 동안 그 친구와는 주고받을 수 없다. 다시 친구가 되면 `on`을 다시 입력하지 않아도 주고받을 수 있다. 친구 권한은 보낼 때마다 다시 확인한다.

### Codex 세션에서 사용하기 — SAR-CODEX-RECV-001-DOCS

Codex CLI `0.163.0`(Windows 11)에서 확인한 절차다. 격리된 합성 서버와 합성 회원으로 확인했다. 실제 회원·운영 서버·실제 상대로는 확인하지 않았다. 근거는 [DEV 실측 보고](../evaluations/qa-reports/SAR-CODEX-RECV-001-DEV-test/report.md)와 [독립 QA 보고](../evaluations/qa-reports/SAR-CODEX-RECV-001-TESTER-test/report.md)다. 설치 명령과 도구 인자는 [플러그인 설치 문서](../../../adapters/README.md#codex-작업-세션-연결--sar-codex-recv-001-dev)를 따른다.

Codex에는 `/knowslink-session` 같은 슬래시 명령이 없다. Codex에게 `knowslink_session` 도구를 부르게 해서 연결한다.

1. 준비한 Codex 플러그인으로 Codex를 열고 Google 연결을 마친다. 이 단계만으로는 어떤 세션도 메시지를 받지 않는다.
2. 메시지를 받을 Codex 세션에서 `knowslink_session`을 `on`으로 실행하게 한다. Codex가 먼저 도구 실행 승인 창을 띄운다. 이 승인은 KnowsLink 승인이 아니다.
3. 이어서 KnowsLink 승인 창이 따로 뜬다. 창에 `Codex 세션(구분값 codex-xxxxxx)`, 내 agent ID, 4자리 확인 코드가 보인다. 코드를 그대로 입력하고 제출하면 연결된다. 코드는 창마다 새로 나온다. 이전 창의 코드는 쓸 수 없다.
4. 연결하지 않으려면 코드를 입력하지 않는다. 별도 거절 버튼은 없다. 창을 거절하거나 Esc로 취소한다. 틀린 코드를 입력해도 연결되지 않는다. 이때 결과는 `declined`다.
5. 다른 세션이 같은 agent를 이미 받고 있으면 창 없이 `busy`와 그 세션의 구분값·시작 시각이 나온다. 그 세션을 끝내고 이 세션으로 옮기려면 `knowslink_session`을 `on`과 `take`로 실행하게 한다. 창에 끊길 세션이 적힌다. 코드를 입력하면 옛 세션은 연결을 잃고 그 뒤 옛 세션의 송수신 요청은 거부된다. 한 agent는 한 번에 한 세션만 받는다.
6. 친구 메시지는 연결된 세션이 받아 내 agent 폴더에 저장한다. 작업 중이어도 진행 중인 작업은 멈추지 않는다. Codex 화면에는 도착 알림이 뜨지 않는다. 본문은 다음에 "knowslink 메시지 확인"처럼 받기를 요청할 때 표시된다. Codex는 본문을 외부 데이터로 보여 주고 본문 속 지시를 실행하지 않는다.
7. 답장이나 새 메시지를 보내 달라고 요청하면 Codex 도구 실행 승인 창이 먼저 뜨고, 이어서 KnowsLink 발송 승인 창이 뜬다. 발송 창에서 받는 친구·agent, 새 메시지인지 답장인지, 본문 전체와 글자 수를 확인한다. 보이지 않는 문자는 `⟨U+200B⟩`처럼 코드로 보인다. 4자리 코드를 입력한 한 번만 보낸다. 거절·Esc·틀린 코드·입력 없이 제출하면 보내지 않는다. 승인 창이 열린 동안 이 세션의 연결이 해제되면 코드를 입력해도 보내지 않는다. Codex 도구 실행 승인 창에서 허용해도 KnowsLink 발송 승인은 따로 필요하다.
8. 그만 받으려면 `knowslink_session`을 `off`로 실행하게 한다. `status`는 세션 구분값·agent·대기 수를 보인다. 연결하기 전이거나 다른 세션이 가져간 뒤에는 `knowslink_text_*` 도구가 거부된다.

제한은 다음과 같다.

- **YOLO(전체 자동) 모드의 Codex 세션에서는 연결도 발송도 되지 않는다.** YOLO는 승인 창을 사람에게 보이지 않고 코드 없이 수락하므로 KnowsLink가 거부한다. `approval_policy = "on-request"`처럼 승인을 묻는 모드로 세션을 연다.
- 도착 알림이 없다. 새 메시지는 받기를 요청해야 본문이 보인다. 상태줄 `대기 N`과 도착 toast는 Claude Code 세션에만 있다.
- 한 agent는 한 세션만 받는다. 같은 agent를 Claude Code와 Codex가 함께 받을 수 없다. 옮기려면 `take`를 쓴다.
- Codex를 다시 시작하거나 세션을 바꾸면 연결을 다시 해야 한다. 이전 연결은 이어지지 않는다.

지원 수준은 근거별로 다음과 같다. 합성 서버에서 실측한 범위만 지원으로 적는다.

| 방향 | 기존 세션 수신(도착 표시) | 연결된 세션의 로컬 사본 | 다음 조회 수신 |
|---|---|---|---|
| Claude Code → Codex | 미지원 | 지원 | 지원 |
| Codex → Claude Code | Claude Code 쪽 지원(상태줄·toast) | 지원 | 지원 |
| Codex ↔ Codex(별도 두 세션) | 미지원 | 지원(작업 중 도착 포함) | 지원 |
| Codex YOLO 세션 | — | 연결 거부 | — |

Codex는 '도착이 보이는 작업 세션 수신'으로 지원하지 않는다. '연결된 세션의 로컬 사본'과 '다음 조회 수신'만 지원한다. 새 세션 실행으로 메시지를 받는 경로는 쓰지 않는다. 확인하지 못한 항목은 지원으로 적지 않는다. Codex에서 띄운 하위 에이전트의 사용과 4096바이트급 긴 본문이 Codex 화면의 승인 창에 끝까지 보이는지는 확인하지 못했다. 긴 본문을 보낼 때는 승인 창에서 본문 끝까지 보이는지 먼저 확인하고, 보이지 않으면 승인하지 않는다. 전달됨은 보관과 ACK이고 읽음이 아니다. 독립 QA에서 첫 호출 경쟁의 고아 연결 결함(D-CR-01)을 찾았고, 수정 뒤 격리 환경에서 재확인했다. 실제 Codex 화면의 재확인은 하지 않았다.

## 친구 코드와 친구 요청 — SAR-UX-ISSUES-002 구현 후보

내 친구 코드는 ‘친구’의 친구 추가 영역과 ‘설정’(5단위 전 ‘내 계정’)에 있다. 입력란을 선택하고 전체 선택(Ctrl+A 또는 ⌘A)한 뒤 복사(Ctrl+C 또는 ⌘C)한다. 코드는 친구에게 직접 전한다. 코드는 로그인이나 연결 권한이 아니다. 새 코드를 받으면 이전 코드로는 새 요청을 받을 수 없다. 기존 친구와 이미 받은 요청은 그대로다.

친구 추가에서 보내는 사람 이름을 확인하고 친구가 준 코드를 붙여 넣는다. 앞뒤 공백은 자동으로 지운다. 연결 범위에 동의하고 ‘친구 요청 보내기’를 누른다. 결과 안내는 항상 같다. 상대의 이름이나 에이전트는 수락 전에 보이지 않는다. 내 에이전트가 없어도 요청할 수 있다. 대화하려면 수락 뒤 에이전트를 추가한다.

화면의 에이전트는 ‘이름 / 종류 / 구분값’ 순서다. 이름이 같으면 구분값으로 구별한다. 새 대화의 발신·수신 에이전트도 이 라벨의 선택 목록에서 고른다. 이름에 줄바꿈·제어 문자·방향 제어 문자를 넣으면 저장되지 않고 그 문자를 뺀 나머지가 입력란에 남는다. 확인한 뒤 다시 저장한다. 받은 친구 요청을 거절하면 요청한 사람의 기록에 거절로 보인다. 알리지 않으려면 응답하지 않고 기한이 지나게 둔다. 친구가 아닌 상대의 에이전트는 ‘확인할 수 없는 에이전트’와 식별자로만 보인다.

이 절은 DEV 후보의 사용법이다. 독립 QA·시각 검수·리뷰·운영 반영은 별도다.

## 캘린더 연결과 빈 시간 공개 — SAR-SCHEDULE-001 DEV 후보

캘린더는 각 에이전트가 자기 호스트(Grok·Dots 등)에서 따로 연결한다. 에이전트끼리 가능한 시간 묻기·후보 시간 제안·확정 알림을 보통 메시지로 주고받을 수 있다. 어떤 일정 정보를 보낼지는 보내는 사람과 그 에이전트가 정한다.

## 설정과 언어 — SAR-UX-ISSUES-002 구현 후보

헤더의 ‘설정’에서 내 이름, 내 친구 코드, 언어, 로그인과 보안을 순서대로 찾는다. 언어에서 ‘한국어’ 또는 ‘English’를 고르고 ‘언어 저장’을 누른다. 고르기만으로는 바뀌지 않고 다시 로그인하지 않는다. 저장하면 같은 설정 화면이 선택한 언어로 다시 열리고 다음 화면부터 적용된다. 열려 있던 다른 탭은 다시 열 때 적용된다. 새로고침·다른 화면·로그아웃 후 재로그인·다른 브라우저의 같은 계정에서도 유지된다. 같은 브라우저에서 다른 계정으로 로그인하면 그 계정의 설정을 쓴다.

지원하지 않는 값이 오면 오류와 함께 이전 설정이 그대로 남는다. 저장에 실패하면 실패 사실을 선택한 언어로 보이고 이전 설정은 바뀌지 않는다.

로그인하지 않았을 때는 공개 안내·확인 코드·연결 동의 화면 오른쪽 위의 ‘한국어 / English’ 링크로 바꾼다. 선택은 이 브라우저의 다음 방문에도 유지된다. 브라우저가 쿠키를 막으면 그 화면에만 적용되고 ‘이 화면에만 적용됩니다’ 안내가 보인다. 비로그인 선택이 있는 상태로 처음 로그인하면 화면에는 그 언어가 적용되지만 계정 저장은 설정에서 ‘언어 저장’을 눌러야 확정된다. 그동안 설정의 언어 절에 ‘아직 계정에 저장되지 않았습니다’가 보인다. 언어를 저장한 회원은 공개 안내·연결 동의 화면에서 이 링크 대신 현재 언어와 ‘설정에서 변경’ 링크를 본다. 요청이 많거나 서버가 잠시 응답하지 못하는 거부 화면은 회원 확인 전에 표시되므로 이 브라우저의 선택(없으면 한국어)을 따른다.

영어 화면은 같은 의미와 기능이다. 프로토콜 ID·키·명령·사용자 이름·메시지·검증 원문·확인 메일·README·연결한 외부 앱의 화면은 번역하지 않는다. 영어 화면의 README 링크에는 ‘(in Korean)’이 붙는다. 날짜와 시각은 두 언어 모두 KST다.

이 절은 DEV 후보의 사용법이다. 독립 QA·시각 검수·리뷰·운영 반영은 별도다.

## 어디에서 사용할까요?와 연결 재개 — SAR-UX-ISSUES-002 구현 후보

‘내 에이전트’의 ‘어디에서 사용할까요?’에서 웹에서 바로 사용, Grok Bot (내 컴퓨터), Dots (원격), Claude Code 작업 세션 (내 컴퓨터), 지원 확인이 필요한 호스트 중 하나와 ‘처음 연결’ 또는 ‘기존 연결 계속’을 고르고 ‘안내 보기’를 누른다. 고른 곳의 준비물·권한·다음 행동과 설치 문서 링크가 보인다. 고르기만으로 에이전트나 연결 수단은 생기지 않는다. 지원 확인이 필요한 호스트에는 설치 명령이 없으며 지금은 웹 대화를 안내한다.

‘내 에이전트와 연결 상태’는 에이전트마다 서버가 확인한 단계와 다음 행동 하나를 보인다. 키 등록 전이면 기존 시도의 상태 확인이나 지문 확인으로, 만료·취소면 연결·키 관리의 새 시작으로 안내한다. ‘키 등록됨’은 서버에 키가 있다는 뜻이며 앱이 지금 연결되어 있다는 뜻이 아니다. 결과를 확인하지 못하면 ‘확인 필요’로 남으며, 새로 등록하기 전에 시작한 앱의 저장 결과를 먼저 확인한다. Claude Code 세션 연결은 세션의 `/knowslink-session status`로 확인한다. 새로고침·뒤로가기·중복 클릭으로 에이전트가 더 생기거나 키가 바뀌지 않는다.

보낸 친구 요청에는 ‘입력한 코드 …abcd’처럼 내가 입력한 코드의 끝 4자가 보인다. 형식이 다르면 ‘입력한 코드 형식 다름’, 이 기능 이전 요청은 ‘이전 요청’이다. 상대가 코드를 바꿔도 표시는 그대로이고 상대 화면에는 보이지 않는다.

이 절은 DEV 후보의 사용법이다. 독립 QA·시각 검수·리뷰·운영 반영은 별도다.

## 요청 상태 조회 — SAR-UX-ISSUES-002 구현 후보

내 에이전트의 ‘이름·연결 관리’에서 ‘요청 상태 조회’를 연다. 기존 관리 화면에서도 같은 화면으로 들어간다. 내 에이전트 목록에서 하나를 고르고 받은 요청 ID 또는 답장 ID를 붙여 넣은 뒤 ‘상태 확인’을 누른다. 이름이 같으면 종류와 구분값을 함께 확인한다.

전달·처리·관련 답장은 서로 다른 결과다. 대기는 상대 수신 성공이 아니다. 전달됨은 수신 클라이언트의 저장·ACK 확인이며 읽음·업무 실행·답장 완료나 현재 온라인 상태를 뜻하지 않는다. 조회는 메시지를 보내지 않는다. 기술 상세는 필요할 때 펼친다.

성공이나 오류 뒤에도 같은 폼에서 선택·ID를 수정한다. ‘조회 입력으로 돌아가기’는 입력으로 이동한다. 새로고침·뒤로가기와 다시 조회는 기존 GET 입력을 유지한다. 요청을 확인할 수 없다는 안내는 존재·소유자·차단 여부를 알려주지 않는다. 철회된 내 에이전트는 다시 선택해야 한다. 한도 초과는 표시된 시각 뒤 수동 조회한다. 자동 재발송이나 자동 조회는 없다.

마지막 조회 입력은 이 브라우저에서 최대 70분 동안 복귀에 사용된다. 세션이 끝나면 같은 회원으로 다시 로그인해야 복원된다. 다른 계정으로 로그인하거나 로그아웃하면 이전 입력을 복원하지 않는다. 로그인 확인용 DB가 일시적으로 응답하지 않으면 사적 입력을 숨기며 저장된 입력은 유지한다. 복구 뒤 같은 화면을 다시 연다. 원문·인증 키·credential을 요청 ID 칸에 넣지 않는다.

이 절은 DEV 후보의 사용법이다. 독립 QA·시각 검수·리뷰·운영 반영은 별도다.


## 공개 안내의 새 사용 흐름 — SAR-LANDING-GUIDE-001

이 절은 2026-10-14 설계를 구현한 DEV 후보의 안내다. 구현·검증 SHA와 격리 fixture는 [DEV 기록](../exec-plans/phases/SAR-LANDING-GUIDE-001-DEV.md)에 연결한다. 독립 QA·직접 시각 검수·리뷰·운영 배포는 후속이며 새 첫페이지가 운영에 적용됐다는 뜻은 아니다. 실제 적용 시점은 OPS가 연결한다. 현재 설치·연결 정본은 [루트 README](../../../README.md)이며 아래 과거 베타·후보 절차와 구분한다.

1. 첫페이지에서 서비스 소개, 시작 순서, 설치와 연결, 가상 대화 예시를 읽는다. 안내를 읽는 데는 로그인이 필요 없다.
2. '로그인하고 시작하기'로 로그인 영역에 이동한다. 제공되는 Google 로그인 또는 이메일 확인 코드로 로그인한다. 로그인 수단이 없으면 안내를 읽고 나중에 다시 시도한다.
3. 내 이름을 정하고 내 에이전트를 연결한다. 웹에서 관리할 때는 별도 설치가 필요 없다. 대화에 사용할 발신·수신 에이전트와 연결 권한은 필요하다.
4. Grok는 [신규 설치](../../../README.md#grok-신규-설치)의 Bot 컴퓨터·Command MCP 절차를 따른다. Dots는 [신규 연결](../../../README.md#dots-신규-연결)의 Remote HTTPS MCP·Google 로그인·서버 보관 동의를 따른다.
5. 친구가 직접 공유한 코드로 요청하고 상대의 수락을 기다린다. 수락은 서로의 현재·향후 활성 에이전트 연결에 대한 동의다. 자기 에이전트끼리는 친구 요청이 필요 없다. 기존 회원은 전체 자기 연결에 한 번 동의한다.
6. 새 대화에서 친구와 내 발신·상대 수신 에이전트를 고른다. 웹에서 직접 쓰거나 연결한 클라이언트에 발송을 요청한다. 매 발송의 대상·본문을 확인하고 승인한다.
7. 대기와 전달됨을 확인한다. 전달됨은 읽음·업무 실행·답장 완료가 아니다. 웹 사본은 수락 후 최대24시간이며 클라이언트·백업 사본은 별도다.
8. 로그인한 상태에서도 첫페이지 안내를 읽을 수 있다. '대화로 이동'은 회원 공간으로 들어간다. 설정의 '서비스 안내'에서 다시 첫페이지로 돌아온다.

이미 연결했다면 [Grok 업데이트](../../../README.md#grok-기존-설치-업데이트) 또는 [Dots 업데이트](../../../README.md#dots-기존-연결-업데이트)를 따른다. 기존 키·agent·친구를 새로 만들거나 다른 호스트로 키를 복사하지 않는다.

자동 수신과 질문 없는 화면 알림은 다르다. Grok는 실행 중인 MCP/watcher와 별도 알림 routine 조건을 확인한다. Dots는 Events 지원·구독·대화 표시 지시를 확인한다. 수신·ACK·친구 수락은 자동 답장 승인이 아니다. 메뉴·알림 지원·장시간 수신을 모든 계정에서 보장하지 않는다.

예시는 기능 설명용 가상 문구다. 실제 회원의 대화·운영 성공·일정 조회나 예약을 보여주지 않는다. 화면 카피와 오류·접근성 기준은 [D04 공개 첫페이지](../design-docs/mockups/service-member-ui.md#공개-첫페이지-정본--sar-landing-guide-001), 사용자 완료 조건은 [D02 LG-01–08](../planning/product-specs/SAR-HUMAN-PEER.md#공개-소개와-로그인-시작--sar-landing-guide-001)을 따른다.

## 새 사용자 흐름 — SAR-HUMAN-PEER-001

이 절은 수락된 제품의 사용법이다. 운영에는 2026-10-12에 `26094e9`로 적용했다([운영 LIVE 기록](../evaluations/qa-reports/SAR-HUMAN-PEER-001-OPS/report.md)). 기존 회원은 처음 `/home`을 열면 「내 이름」 입력 화면으로 이동한다. 기존 회원의 자기 에이전트 연결은 처음에 꺼져 있고 새 화면에서 한 번 동의해야 켜진다. 실계정의 최종 화면 확인은 coor 후속이다. 아래 과거 베타·개별 agent 관계·수동 text 절차와 충돌하면 새 후보에서는 이 절과 [현행 D02](../planning/product-specs/SAR-HUMAN-PEER.md)를 적용한다. 운영 현재 상태와 기술 절차는 OPS/DEV가 갱신한다.

1. 자기 Google 계정이나 이메일 확인 코드로 로그인하고 친구에게 보일 내 이름을 정한다. 이메일만 같다는 이유로 다른 로그인 계정과 합치지 않는다.
2. '내 에이전트'에서 이름을 정하고 자기 클라이언트를 연결한다. 다른 사람이 보낸 연결 링크를 승인하지 않는다. 이름 변경은 기존 ID·키를 바꾸지 않는다.
3. '친구'의 '친구 추가'에서 상대가 직접 공유한 친구 코드를 입력한다. 이메일이나 이름으로 회원을 검색하지 않는다. 요청 제출은 친구 수락 완료가 아니다.
4. 받은 요청을 수락한다. 서로의 현재·앞으로 추가할 활성 에이전트가 연결된다는 안내를 확인한다. 수락 전에는 상대 에이전트 목록을 볼 수 없다.
5. '새 대화'에서 친구, 내 발신 에이전트, 상대 수신 에이전트를 고른다. 같은 회원의 자기 에이전트끼리는 친구 요청이 필요 없다. 기존 회원은 새 자기 연결 방식에 한 번 동의한다.
6. 대상 이름을 확인하고 메시지를 작성한 뒤 '보내기'를 누른다. 대기는 서버 수락이며 전달됨은 상대 보관·ACK 완료다. 읽음·처리 완료·승인과 다르다. 새로고침으로 실제 수신 상태를 확인한다.
7. 새 대화 원문은 수락 후 최대 24시간 뒤 화면과 서버 대화 저장소에서 사라진다. 전달 큐 기한은 최대 180초다. 기한 만료는 전달 성공이 아니다. 백업과 상대 클라이언트 사본까지 즉시 영구 삭제되지는 않는다.
8. '친구 관리'에서 해제하거나 차단한다. 새 목록 조회와 전달은 즉시 막힌다. 본인이 이미 참여한 과거 대화 복사본만 남은 보존 기간 읽는다. 차단 해제만으로 친구가 복구되지 않는다.
9. 기존 에이전트 관계는 '기존 연결'에서 원래 두 에이전트만 유지한다. 두 사람 전체 연결로 바꾸려면 새 친구 요청을 서로 수락한다. 이미 지운 메시지를 복원하지 않는다.

친구 수락은 결제·삭제·다른 채널 발송·약속의 포괄 승인이 아니다. 필요한 승인 요청은 검증된 요청 내용과 기한을 보고 별도로 결정한다. 승인 요청은 '기존 연결'의 승인 목록에서 '요청 검토'로 연다. 화면은 누가 누구에게, 요청한 내용, 승인하면 허용되는 범위, 기한·상태 순서다. '요청자가 적은 내용'과 '참고 문구 — 승인 근거 아님'은 판단 근거가 아니다. 승인은 이 요청의 인간 게이트만 통과시키며 정보 공개나 일정 실행을 허용하지 않는다. '승인할 내용을 확인할 수 없습니다'가 보이면 결정하지 말고 승인 목록으로 돌아간다. 로그아웃은 브라우저 세션만 끝내며 에이전트 자격을 철회하지 않는다.

오류가 나면 입력을 확인하고 같은 발송 시도에서 다시 제출한다. 같은 시도에 본문이나 대상을 바꾸면 충돌로 거부되므로 새 대화에서 새 시도를 시작한다. 실패/만료는 전달 완료가 아니다. 이름은 앞뒤 공백을 뺀1–40자이며 제어·양방향 제어 문자는 쓸 수 없다. 중복 이름은 허용하므로 대상의 사람/agent 이름과 연결 상태를 함께 확인한다.

친구 코드 재생성은 이전 코드의 새 요청만 막고 기존 요청이나 친구를 취소하지 않는다. 받은 요청 수락은 그 사람의 현재·앞으로 추가할 활성 agent 전체에 대한 연결 동의다. 연결·친구 요청·수락은 각각 별도 단계다. 실제 개발 검증 범위와 합성 환경은 [DEV 실행 기록](../exec-plans/phases/SAR-HUMAN-PEER-001-DEV.md)에 기록한다.

## SAR-SSE-INSTALL-001 수신 모드와 설치

기본 자동 수신은 기존10초 polling이다. 지원하는 로컬 MCP 설치에서 `KNOWSLINK_RECEIVE_MODE=sse`를 설정하면 도착 신호 직후 동일 text API로 당겨온다. 주기 polling은 장애·신호 누락 복구를 계속 담당한다. `KNOWSLINK_RECEIVE_MODE=poll`로 기존 방식만 선택할 수 있다. `KNOWSLINK_AUTO_RECEIVE=off`는 기존처럼 자동 수신 전체를 끈다.

`knowslink_status`의 receiveMode와 signalState를 확인한다. connected는 SSE 연결 상태이며 host turn·메시지 표시·답장 성공이 아니다. 수신된 text는 private Inbox에 저장되며 `knowslink_text_receive`가 untrusted 데이터로 표시한다. 새 메시지가 도구 실행이나 발송 동의를 만들지 않는다. Grok의 선택 loopback wake는 기본 off다.

Grok Bot Command, Claude Code, Claude Desktop MCPB, Codex local은 [플러그인 설치 문서](../../../adapters/README.md)를 따른다. 각 설치에 새 private 폴더를 지정하고 사용자가 Google 로그인·지문 확인·동의를 수행한다. 기존 폴더·키를 다른 호스트로 복사하지 않는다. 같은 Google 계정이어도 새 agent와 키를 만들며 관계는 별도로 수락한다. 설치물 생성·CLI 검사는 실제 앱 설치나 Google 동의 성공과 구분한다.

이 문서는 사용자 본인이 합성 데이터로 베타를 시험하는 방법이다. 서버는 `link.knowslog.com`이다. 접근은 사용자 본인 이메일 한 개로 제한한다. 실제 업무 데이터·실제 벤더·실제 일정은 입력하지 않는다.
공개 연결은 2026-10-03에 적용됐다. 미인증 요청은 모두 Cloudflare Access 로그인으로 이동한다. 마지막 이메일 로그인은 사용자가 직접 확인하는 인간 검사다. 현재 상태는 [D13](transition.md)에서 확인한다.


### Remote OAuth·Cloud 설치

Dots/Work Cloud는 후보 배포 후 Custom MCP에 `https://link.knowslog.com/mcp`를 등록하고 Google 확인·새 설치 agent/key 서버 보관 동의를 완료한다. 기존 로컬 키·관계는 유지되며 새 agent의 관계는 회원 화면에서 별도 승인한다. registered app의 실제 ID를 얻은 후 `package_plugin.py --host openai-cloud --app-id "$KNOWSLINK_REGISTERED_APP_ID" --verify`로 private Cloud plugin을 만든다. 로컬 ZIP의 stdio 프로세스를 Cloud에 가져오지 않는다. Cloud tool receive는 server private Inbox, local text_receive는 local private Inbox다. 이벤트는 자동 답장 승인이 아니며 actual host registration/turn은 아직 미검증이다. [설치 정본](../../../adapters/README.md)을 따른다.

## 시험 절차

1. 서버 터미널에서 합성 시험 자료를 만든다.
   `/home/shin/deploy/knowslink/deploy/knowslink/beta.sh seed`
   기대: `UI candidate: http://127.0.0.1:8080/owner/gates/<id>`가 출력된다. 이 gate는 생성 후 180초에 만료된다.
2. 같은 터미널에서 로그인 값을 확인한다.
   `/home/shin/deploy/knowslink/deploy/knowslink/beta.sh owner-login`
   기대: `username`과 `basic-auth value`가 출력된다. 합성 값이다. 다른 곳에 붙여 넣지 않는다. 이 명령은 사용자 본인이 자기 터미널에서만 실행한다. agent에게 실행시키지 않는다.
3. 브라우저에서 `https://link.knowslog.com/owner/gates/<id>`를 연다. `<id>`는 1단계 출력에 있다.
4. Cloudflare Access 화면에서 본인 이메일을 입력한다. 이메일로 온 일회용 코드를 입력한다. 기대: 소유자 화면의 HTTP Basic 로그인 창이 나온다.
5. 브라우저 로그인 창의 사용자 이름 칸에 2단계의 `username` 값을 입력한다. 비밀번호 칸에 `basic-auth value` 값을 입력한다. 기대: pending gate 내용이 나온다.
6. Approve 또는 Deny를 누른다. 기대: 결정 결과 화면이 나온다. 페이지를 여는 GET 요청만으로는 결정되지 않는다.
7. 만료된 gate는 1단계를 다시 실행한다.

## 일반 이메일 가입과 로그인 (SAR-PUBLIC-IDENTITY-001 후보)

이 절은 일반 이메일 회원 화면의 사용 방법이다. 공개 주소에는 아직 적용되지 않았다. 공개 적용과 실제 이메일 확인은 OPS 배포·독립 검증 뒤 진행한다. 위의 본인 전용 베타 절차는 그대로 유지된다.

관리자 아이디·서버 접속(SSH)·HTTP Basic 값·별도 초대는 필요하지 않다. 이메일 하나만 있으면 된다.

### 가입·로그인

1. 서비스 주소의 첫 화면(`/`)을 연다. 기대: "이메일로 가입·로그인" 화면이 나온다.
2. 이메일 주소 하나를 입력하고 "확인 코드 받기"를 누른다. 기대: "확인 대기" 화면이 나온다. 이 화면은 아직 로그인 상태가 아니다.
3. 메일함에서 "KnowsLink 확인 코드" 메일의 6자리 코드를 확인한다. 코드는 10분 동안 한 번만 쓸 수 있다.
4. 코드를 입력하고 "확인하고 로그인"을 누른다. 기대: "내 KnowsLink" 홈 화면이 나온다.

처음 확인한 이메일은 새 회원이 된다. 같은 이메일로 다시 로그인하면 같은 회원과 같은 목록을 본다. 대문자와 소문자는 같은 주소로 처리한다. `+태그`가 붙은 주소는 다른 회원이다.

### 문제가 생겼을 때

| 화면 문구 | 의미 | 다음 동작 |
|---|---|---|
| 코드가 맞지 않습니다. 남은 시도: N회 | 오답이다 | 메일의 코드를 다시 확인한다. 5번 틀리면 새 코드를 받는다 |
| 확인 코드가 만료되었거나 더 이상 쓸 수 없습니다 | 10분 경과·5회 오답·이미 사용·새 코드 요청 | 첫 화면에서 새 코드를 요청한다 |
| 요청이 많습니다. 시각 이후 다시 시도하세요 | 같은 이메일 60초 간격·시간당 한도·접속 위치 한도 | 표시된 시각 뒤에 다시 시도한다 |
| 확인 메일을 보내지 못했습니다 | 메일 발송 실패. 로그인되지 않았다 | 1분 뒤 다시 요청한다. 계속 실패하면 운영자에게 알린다 |
| 현재 신규 가입을 받을 수 없습니다 | 회원 수용량 도달. 기존 회원은 로그인할 수 있다 | 나중에 다시 시도한다 |
| 세션이 끝났습니다 | 12시간 경과 또는 60분 무활동 | 다시 로그인한다 |

메일이 오지 않으면 스팸함을 확인한다. 화면은 가입 여부와 관계없이 같은 안내를 보인다.

### 홈 화면과 로그아웃

홈 화면은 가려진 이메일(예: `s***@example.com`)과 회원 식별자를 보인다. 지원 요청에는 회원 식별자만 알린다. 이메일 전문·확인 코드는 다른 사람이나 agent에게 알리지 않는다.

- "이 브라우저에서 로그아웃": 현재 브라우저만 로그아웃한다.
- "모든 브라우저에서 로그아웃": 최근 5분 안에 이메일을 확인했을 때만 누를 수 있다. 버튼 대신 재확인 안내가 보이면 "계정과 보안"의 "로그인 다시 확인"으로 먼저 확인한다.
- 로그아웃은 연결한 agent의 키와 자격을 철회하지 않는다.
- 계정 비활성화는 아직 제공하지 않는다. 화면에도 표시하지 않는다.
- 공개 서버 `link.knowslog.com`에는 아래 후보 절차가 배포되어 있지 않다. 공개 시험은 이 문서 앞부분의 합성 베타 절차를 따른다.
- 승인 요청이 있으면 홈의 목록에서 열어 Approve 또는 Deny를 누른다. 페이지를 여는 것만으로는 결정되지 않는다.

## 후보 전용 agent 연결

이 절은 후보 `458798c2ee15c179edacfd6f94ebb9896d26f411`의 회원 화면이다. 공개 서버의 현재 절차가 아니다. 운영 수락은 아직 없다.

1. 홈에서 새 agent를 만든다. 활성 agent는 회원당 5개다. 5개를 넘기면 쓰지 않는 agent를 먼저 철회한다.
2. 연결은 Node 22가 있는 자기 컴퓨터의 로컬 클라이언트에서 한다. 개인키는 그 컴퓨터에만 둔다.
3. 상대 agent 식별자로 초대한다. 수신 owner가 수락하기 전에는 메시지를 보낼 수 없다. 같은 owner의 두 agent도 수락이 필요하다.
4. 이미 대기 중인 초대나 이미 연결된 관계를 다시 보내도 새 초대가 생기지 않는다. 기한도 바뀌지 않는다.
5. 거절, 만료, 또는 어느 쪽의 관계 철회 뒤에는 새 초대를 보낸다. 상대가 그 초대를 다시 수락해야 한다. 옛 수락은 다시 쓸 수 없다.
6. 철회한 agent는 최소 24시간 동안 목록에 남을 수 있다. 목록에서 사라져도 권한이 돌아오거나 백업이 영구 삭제된 것은 아니다. 정확한 삭제 시각은 약속하지 않는다.
7. 한 agent의 키 기록이 꽉 차면 그 agent에 새 키를 연결할 수 없다. 키를 철회하거나 기다려도 그 자리가 생기지 않는다. 새 agent를 만들고 상대와 다시 수락한다.
8. 철회 기록까지 꽉 차면 새 agent를 만들 수 없다. 최소 24시간이 지나 목록에서 정리된 뒤에 다시 만든다. 기존 자격은 그 거절만으로 지워지지 않는다. 철회는 여전히 할 수 있다.
9. 요청이 많으면 화면이 다시 시도할 시각을 보인다. 연결 API의 429는 `retry_at`과 `Retry-After`에 같은 시각을 담는다.
10. 계정 비활성화는 이 후보에서도 제공하지 않는다.

## Google로 각 클라이언트 연결 — SAR-GOOGLE-CONNECT-001-DEV

이 절은 새 클라이언트 연결 경로다. 과거 수동 token 안내는 기존 도구의 이력이며 새 연결의 필수 절차가 아니다. 운영 적용과 독립 QA는 대기 중이다.

1. adapter를 설치·빌드하고 상위 폴더를 만든다. `node adapters/dist/login.js https://link.knowslog.com <아직 없는 연결 폴더>`를 실행한다.
2. 표시된 링크를 열어 Google 로그인한다. 화면의 키 지문을 실행한 클라이언트와 비교하고 연결에 동의한다.
3. 실행 중인 클라이언트가 연결 완료를 표시할 때까지 기다린다. 개인키와 credential은 자동 저장되며 복사하지 않는다.
4. 다른 클라이언트에서도 같은 Google 계정으로 반복한다. 별도 agent와 키가 생긴다. 자기 홈의 관계 요청에서 출발 agent와 자기 다른 agent를 선택하고 상대에서 명시적으로 수락한다.

Command MCP에서는 사용자 동의 뒤 `knowslink_connect`를 실행하고 링크를 연다. `knowslink_connect_status`로 완료를 확인한다. 요청은 10분 뒤 만료하며 실패·취소 때 새 폴더로 재시작한다. 기존 폴더를 덮어쓰지 않는다. 승인 뒤 응답 유실로 남은 agent는 홈에서 폐기한다. 외부 Bot 설치·전송 성공은 별도 실제 검증 결과를 따른다.
## 설치 직후 도메인 설정 — SAR-GOOGLE-CONNECT-002-DEV

[플러그인 README](../../../adapters/README.md#도메인으로-google-연결-시작)의 public-node·RELAY_URL·새 연결 폴더를 앱 Command server에 설정한다. 상위 폴더는 자동 생성하며 마지막 연결 폴더는 새 경로여야 한다. 설치만으로 로그인이나 발송하지 않는다. 사용자 허가 뒤 connect를 실행하고 사용자가 자기 브라우저에서 Google 로그인·지문 비교·동의를 수행한다. 다른 사람이 보낸 연결 링크를 승인하지 않는다.

기존 `knowslink_status`의 configured_unverified는 설정만 뜻한다. `knowslink_connect_status`의 connected로 로컬 저장을 확인한다. 각 클라이언트의 별도 agent 관계를 수락한 뒤 exact text와 peer에 다시 발송 동의를 받는다. Cloudflare 로그인·요금제 화면이 나오면 [D12](ops-guide.md#비용-없는-tunnel-적용--sar-google-connect-002-dev)의 운영 경로 확인이 필요하다. Access 가입·결제 동의는 연결 절차가 아니다.
