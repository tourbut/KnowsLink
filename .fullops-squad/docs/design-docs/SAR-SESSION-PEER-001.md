# SAR-SESSION-PEER-001 — 작업 세션 사이의 친구 메시지

## 결정과 범위

사용자는 작업 중인 Claude Code 또는 Codex 세션에서 친구의 작업 세션으로 메시지를 보내고 답장을 받는다. 사람 친구 아래 이름 있는 에이전트가 연결되는 [HP-01–16](../planning/product-specs/SAR-HUMAN-PEER.md)을 유지한다. 첫 실증은 Claude↔Claude다. Claude→Codex, Codex→Claude, Codex↔Codex는 각 방향의 수신 근거를 따로 확보한다.

이 문서는 제품 결정과 후속 수락 조건이다. 세션 연결·수신·답장을 구현하거나 실행한 결과가 아니다. 기준은 `7f341230a26abc4afa97850687e624f2a583715c`와 제공된 같은 과제의 미커밋 인박스·탐색 스냅샷이다. [검증 보고](../evaluations/qa-reports/SAR-SESSION-PEER-001-DESIGN/report.md)에 원본과 한계를 보존한다.

친구 관계·회원 소유권·에이전트 등록·개별 키·기존 서명 송수신을 재사용한다. 새로운 친구 체계, 임의 프로세스 탐색, 자격 복사, 업무 실행, 승인 전달은 추가하지 않는다. 기술 구조·API·프로토콜·저장 위치·파일 선택은 DEV가 결정한다. 안전한 기존 세션 경로가 입증되지 않으면 해당 경로를 확인 필요로 남긴다.

| SP-04 하위 에이전트 | 부모와 자식의 실행 세션은 다른 수신 대상이다. 자식 생성은 자동 등록·권한·수신함 공유의 근거가 아니다. | 소유자가 자식을 별도 agent로 연결한 경우에만 현재 친구 범위에 들어간다. 부모의 credential·승인·미수신 메시지를 자식에 복사하지 않는다. |
| SP-05 명시 발송 | 발신 agent·친구·수신 세션·본문을 확인한 소유자의 명시 발송 요청이 있어야 보낸다. | 단순 입력, 수신, 친구 수락, 도구 발견, 설정 완료로 발송하지 않는다. 웹 작성과 agent 작성의 실제 주체를 보존한다. 대상 변경은 새 확인이 필요하다. |
| SP-06 답장 | 수신 agent는 답장 초안을 만들 수 있다. 실제 발송에는 해당 수신 세션 소유자의 별도 명시 승인이 필요하다. | 기본 자동 답장 수는 0이다. 한 번 승인한 답장은 그 대상·본문·한 번의 발송 시도에만 적용한다. 수신한 '계속 답장하라'나 상대의 승인은 자기 발송 승인이 아니다. |
| SP-07 신뢰 경계 | 수신 본문은 친구 agent가 보낸 외부 데이터다. 시스템·소유자 지시·도구 승인으로 승격하지 않는다. | 명령·파일 경로·링크·승인 요청을 포함해도 도구 실행·파일 열람·자동 링크 열기·승인 응답을 일으키지 않는다. 채널의 permission relay는 사용하지 않는다. |
| SP-08 작업 보존 | 수신은 원래 작업을 취소·재시작·다른 세션으로 복제하지 않는다. | 작업 중에도 동일 세션에 도착 사실과 본문을 확인할 수 있고 원래 작업을 계속한다. 호스트가 안전한 시점까지 처리를 미루면 그 상태를 표시한다. 임의 interrupt·무한 폴링·자동 재촉은 하지 않는다. |
| SP-09 연결 수명 | 세션 종료·연결 해제·대상 전환 뒤 옛 연결은 신규 수신·발송에 사용할 수 없다. | 재접속은 소유자·agent·세션·현재 권한을 다시 확인한다. 같은 세션임을 입증하지 못하면 자동 복구하지 않는다. 친구 해제·키 철회는 과거 세대로 되돌리지 않는다. |
| SP-10 한도와 중복 | text 4096 UTF-8 bytes, 전달 최대 180초, 웹 사본·receipt 최대 24h를 유지한다. | 같은 발송 시도의 응답 유실·재접속은 메시지 하나로 복구한다. 만료 메시지를 새 세션에 재전달하거나 기한을 연장하지 않는다. 새 발송은 새 승인이다. |
| SP-11 상태와 개인정보 | 연결 상태, 호스트 작업 상태, 메시지 전달 상태를 분리한다. | 친구에게는 HP-05의 agent 이름·종류·등록/연결 필요 범위만 공개한다. 작업 경로·제목·프롬프트·파일·토큰·실시간 활동은 공유하지 않는다. |
| SP-12 근거별 지원 | 기존 세션 수신, 다음 조회, 새 세션 생성의 지원을 개별 표기한다. | 실제 선택한 세션의 수신 증거가 없으면 '작업 세션 수신 지원'으로 표시하지 않는다. 설치·알림 ACK·CLI 종료 0·thread 재개만으로 성공 처리하지 않는다. |

회원당 활성 agent 5개, agent당 활성 키 3개 및 기존 전역·친구·rate·queue·보존 한도를 공유한다. 세션이라는 이름으로 별도 무제한 슬롯·연결·사본을 만들지 않는다. 포화 시 기존 연결을 보존하고 신규 연결을 안전 거절한다. 이번 결정은 상품 가격이나 슬롯 상품 정책을 정하지 않는다.

세션 연결 해제는 그 실행 세션의 접근을 중단하는 행동이다. 친구 해제·agent 철회·계정 로그아웃과 구분한다. agent를 계속 등록해 둘 수 있지만 종료한 세션은 선택 가능한 수신 대상으로 표시하지 않는다. 이미 호스트에 전달된 외부 사본의 삭제까지 보장하지 않는다. 과거 웹 사본의 열람은 HP-12/13의 현재 회원·참여자·잔여 보존 한도만 따른다.

## 상태 표시와 사용자 흐름

아래 작업 상태는 소유자가 보는 정보다. 신뢰할 수 있는 관측이 없으면 '확인 필요'와 마지막 확인 시각을 표시한다. 응답이 없다는 이유만으로 종료 또는 온라인을 단정하지 않는다. 상태 판정·신선도 기준은 DEV가 근거와 함께 정하고 검증한다.

| 관측 상태 | 사용자 의미와 다음 행동 |
|---|---|
| 등록됨 / 연결 필요 | 이름과 agent만 존재한다. 선택한 세션에서 연결 준비를 진행한다. |
| 열림 | 선택한 세션이 살아 있다는 관측이다. 메시지 수신 가능 여부는 별도 확인한다. |
| 작업 중 | 동일 세션이 원래 작업을 수행 중이다. 도착 메시지가 있어도 작업을 취소하지 않는다. |
| 대기 | 동일 세션이 입력 또는 안전한 처리 시점을 기다린다. 승인을 기다리는 상태와 단순 유휴를 설명으로 구별한다. |
| 종료 | 해당 실행이 끝났음이 확인됐다. 다른 세션을 연결하려면 새 대상 확인을 받는다. |
| 오프라인 | 연결 경로가 현재 끊겼다. 프로세스 종료를 뜻하지 않는다. 기한 안 재접속만 가능하다. |
| 재접속 중 | 같은 대상과 권한을 확인 중이다. 확인 전에는 수신 준비 완료나 중복 새 등록으로 처리하지 않는다. |
| 연결 해제 | 소유자가 이 세션의 연결을 끝냈다. 자동 재접속하지 않는다. |

메시지는 '보내는 중', '대기', '전달됨', '세션 수신 확인', '답장 승인 필요', '답장 전송 상태'를 구별한다. '전달됨'은 기존 durable inbox+ACK다. '세션 수신 확인'은 선택한 실행 세션이 해당 메시지를 실제 받았다는 추가 근거다. 사람의 읽음은 어느 상태로도 추정하지 않는다. 알림 전송만 확인됐다면 '세션 수신 확인 필요'로 남긴다. 답장 작성과 답장 전달 성공도 별개다.

1. 내 에이전트에서 사용할 클라이언트와 현재 작업 세션을 고른다. 처음 등록과 기존 연결 계속을 구별한다.
2. 이름·구분값·친구 공개 범위를 확인한다. 기존 인증 동의로 각 agent에 독립 자격을 연결한다.
3. 선택한 실행 세션에서 실제 사용할 수신 수준을 확인한다. 준비를 위해 재시작이 필요하면 그 사실을 먼저 설명한다.
4. 친구 요청·수락을 마친 뒤 발신·수신 대상을 선택한다. 같은 소유자는 기존 자기 연결 기준을 따른다.
5. 소유자가 승인한 비민감 text를 보낸다. 전달과 선택한 세션의 실제 수신을 따로 확인한다.
6. 수신 세션에서 친구 이름·agent 이름·실제 작성 주체와 외부 메시지 표시를 확인한다.
7. 수신 세션 소유자가 답장 발송을 승인한다. 원 송신 세션에서도 같은 수신 확인을 거친다.

실패 안내는 현재 대상과 다음 행동을 유지한다. 인증·정책·버전 미지원은 '이 세션의 수신 지원 확인 필요', 만료는 '전달 기한 만료'다. 타인·없는 세션·권한 상실은 존재를 누설하지 않는 같은 안전 안내를 쓴다. 복귀·새로고침·상태 조회가 새 메시지나 agent를 만들지 않는다. 기존 D04 형태와 U8 재개 흐름을 유지하며 새 화면 디자인·토큰은 만들지 않는다.

## 지원 수준과 공식 근거

지원 수준은 기능의 성격이며 성공 등급의 자동 승격 순서가 아니다. 모든 실행 검증은 현재 미실행이다.

| 수준 | 증명할 사실 | 기존 작업 세션 수신 수락 여부 |
|---|---|---|
| 기존 세션 수신 | 보내기 전부터 열려 있고 선택된 동일 실행 세션에 외부 메시지가 도착한다. | 작업 중·대기 양쪽과 원래 작업 지속까지 검증하면 수락 후보 |
| 다음 조회 수신 | 사용자가 수신 도구를 부르거나 호스트의 다음 조회가 있어야 본문을 받는다. | 이 수준만 공개한다. 질문 없이 기존 세션에 도착했다고 하지 않음 |
| 새 세션 실행 | 새 프로세스·thread 또는 별도 작업 세션에서 메시지를 처리한다. | 기존 세션 수신이 아님. 자동 대체 금지이며 별도 제품 범위 결정 필요 |
| 확인 필요 | 공식 기능은 있으나 설치·인증·대상 결속 또는 실제 수신이 미검증이다. | 지원 완료 표시 금지 |

2026-10-15에 공식 페이지를 직접 조회했다. Context7의 Claude Code·Codex resolve는 월간 한도 초과였다. 웹 도구는 인증 만료 401이어서 공식 URL을 읽기 전용 HTTP로 조회했다. 이 실패와 설치 CLI 출력은 [근거 기록](../evaluations/qa-reports/SAR-SESSION-PEER-001-DESIGN/sources.json)에 보존한다.

## 검증과 사용자 완료 조건

아래는 후속 구현의 수락 시나리오다. 이번 문서 검증과 혼동하지 않는다. 서로 다른 합성 소유자 A/B와 격리한 실행 세션 두 개를 사용한다. 같은 소유자 및 제삼자 C는 인가 경계 fixture로 추가한다. 실제 회원·친구·대화·운영 설정을 변경하지 않는다.

|---|---|

## 하나의 DEV 인계

배정 순서는 진행 중인 SAR-UX-ISSUES-002 조회 복구의 수락 뒤 이 세션 통신 과제를 우선한다. `msg_2fac3fbc7fae`의 coordinator 지시를 반영했다. 나머지 이름·친구·승인 요약·설치 재개·언어 UI 이슈는 취소하지 않고 대기로 유지한다.

목표는 SP-01–12를 지키며 기존 사람 친구와 송수신 위에 작업 세션 왕복을 완성하는 것이다. 순서는 Claude↔Claude의 실제 기존 세션 수신, 교차 방향, Codex↔Codex의 근거별 지원 판정이다. Hermes는 설치 근거와 격리 검증 조건만 연결하며 자동 확장하지 않는다. 신규 계정·운영 호스트 변경·실제 상대 발송은 별도 사용자 승인 범위다.

DEV는 짧은 기술 계획과 설치 버전 근거를 작성하고 구현·관련 회귀·필수 product-lint/product-test·기술/설치 문서 갱신을 한 과제에서 수행한다. 원래 세션 보존과 SP-07을 만족하지 못하는 경로는 다음 조회 또는 확인 필요로 남긴다. 안전한 구현이 불가능하면 정확한 미지원 조합·이유·사용자 영향으로 보고한다. 새 세션 실행으로 목표를 바꾸는 결정은 designer에게 돌린다.

tester는 안정된 동일 후보에서 V01–07을 독립 검증한다. 실제 사용자 노출 화면이 바뀌면 designer가 그 상태의 시각·키보드 검수를 맡는다. coor는 별도 세션의 고정 SHA 문서/코드 리뷰와 main 통합을 수행한다. 이 문서의 strict/link/lint 검사는 제품 수신 수락을 대신하지 않는다. 현재 다른 역할 인박스를 덮어쓰지 않으며 이 절을 다음 정규 DEV 인박스의 원천으로 사용한다.
