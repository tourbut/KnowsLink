# SAR-UX-ISSUES-002 — 잔여 UI 이슈의 제품 결정과 순차 인계

## 적용 범위와 근거

이 문서는 #2–#8의 남은 제품 규칙을 확정한다. 설계 완료이며 구현·운영·접근성 수락은 아니다. 입력은 2026-10-15의 [이슈 원문 스냅샷](../evaluations/qa-reports/SAR-UX-ISSUES-002-DESIGN/issues-open.json)과 체크아웃 `76ec89fe66cbeea5c2ffb33ff07015fd722029b3`다. 지시서 기준은 `458eb565c4a1551ec58c70f14aa164d9024241d3`다. 착수 당시 same-key route/find/context/packet과 역할 지시서는 명시적 미커밋 스냅샷이다.

최신 사용자 합의와 [사람 친구 D02](../planning/product-specs/SAR-HUMAN-PEER.md)의 HP-01–16을 우선한다. 친구는 사람 사이의 관계다. 수락 범위는 양쪽의 현재·앞으로 추가할 활성 에이전트다. 이슈 원문의 개별 에이전트 초대와 같은 소유자 사이의 매번 수락 요구는 새 구현 기준으로 사용하지 않는다. 기존 회원의 자기 에이전트 전체 연결에 대한 한 번의 동의와 legacy 두 에이전트의 정확한 범위는 유지한다.

[D04](mockups/service-member-ui.md)의 현행 사람 중심 토큰·형태와 공개 첫페이지 규칙을 유지한다. 이 문서는 회원 보조 화면과 설정·설치 재개 요구의 추가 명세다. D04 원본, 제품 코드, 다른 역할 인박스, PLANS와 board를 수정하지 않는다. DEV가 진행 중인 공개 페이지 CSS 두 결함은 별도 선행 과제다. 과거 visual `ad5ee194`를 이 설계나 새 구현의 수락으로 재사용하지 않는다.

## U2 — 이름·친구 코드·불변 식별자

사용자 지정 handle은 이번 범위에서 도입하지 않는다. 공유 목적은 기존 사람 친구 코드로 충족한다. 화면의 세 개념은 ‘에이전트 이름’, ‘내 친구 코드’, ‘에이전트 식별자’로 고정한다. 친구 코드를 에이전트 handle이나 인증 수단이라고 부르지 않는다.

이름은 현재 규칙인 공백 정리 후 Unicode 1–40자, 제어문자·방향 제어문자 금지를 유지한다. 동명은 허용한다. 카드·선택·승인·조회·연결 화면은 이름을 먼저 보이고 클라이언트와 비밀이 아닌 안정 구분값을 병기한다. 구분값이 충돌하면 표시를 늘려 구별한다. 구분값은 검색·라우팅 키가 아니다. 전체 ID는 상세에 둔다. 권한상 이름을 확인할 수 없으면 ‘확인할 수 없는 에이전트’와 허용된 식별자만 표시한다. 이름을 얻으려고 상대의 현재 비공개 프로필을 추가 조회하지 않는다.

2026-10-19 NAMES-VISUAL 결정: 이름에 금지 문자가 있어 거부하면 ‘이름에 줄바꿈·제어 문자·방향 제어 문자는 쓸 수 없습니다. 보이는 글자로 1–40자를 입력하세요.’를 보인다. 길이·빈 이름 오류는 ‘이름은 1–40자로 입력하세요’를 유지한다. 입력란에는 금지 문자를 제거한 나머지를 남기고 자동 저장하지 않는다. 에이전트 이름·에이전트 추가·내 이름에 같은 규칙을 쓴다. 닫힌 select가 좁은 폭에서 구분값을 숨기면 그 선택기는 조회와 같은 radio 라벨(`이름 / 종류 / 구분값`, 줄바꿈)로 바꾼다. 새 대화의 발신·수신 선택기가 이에 해당한다. 근거: [시각 판정](../evaluations/qa-reports/SAR-UX-ISSUES-002-NAMES-VISUAL/report.md).

내 계정과 친구 추가 화면에서 본인의 친구 코드를 쉽게 찾게 한다. 기본 선택·복사 가능한 읽기 전용 입력과 보이는 라벨을 사용한다. 키보드로 전체 선택·복사가 가능해야 한다. CSP를 완화하거나 복사 JS를 추가할 필요가 없다. 친구 초대 전용 링크는 이번 최소 범위에서 만들지 않는다. 연결 인증 URL을 친구에게 공유하는 대체 경로로 쓰지 않는다.

코드는 시스템이 발급한 무작위 값을 그대로 사용한다. 대소문자를 합치거나 Unicode 정규화로 다른 코드에 매핑하지 않는다. 앞뒤 공백만 제거하며 빈 입력은 로컬 형식 오류로 안내한다. 사용자 지정 handle이 없으므로 handle 중복·예약어·재사용 정책도 적용하지 않는다. 서버 코드 충돌을 다른 계정으로 연결해서는 안 된다. 교체된 옛 코드는 새 요청 발견에 사용할 수 없고 다른 사람에게 재할당하지 않는다. 기존 친구와 이미 받은 요청은 유지한다. 코드 교체는 친구 해제·차단을 대신하지 않는다.

완료 조건 U2-A: 이름 변경 뒤 ID·키·소유·관계·라우팅이 같다. 기존 무명·동명·40자 한글/영문·이모지·잘못된 제어문자를 확인한다. 수동/device/remote 세 생성 경로의 이름이 웹과 클라이언트의 같은 인스턴스를 가리킨다. 이름 오류·재시도로 에이전트를 중복 생성하지 않는다. 보조 화면은 현재 권한으로 허용된 이름만 사용한다.

## U4 — 사람 친구 요청

친구 추가에는 내 이름, 상대가 직접 준 코드, 현재·향후 활성 에이전트 연결 범위, 명시적 동의, ‘친구 요청 보내기’를 배치한다. 보내기 전에 자기 이름과 입력 코드를 확인할 수 있게 한다. 상대 이름·에이전트의 미리보기는 제공하지 않는다. 이름이나 이메일 검색·공개 회원 목록도 없다.

내 에이전트가 없어도 사람 친구 요청은 가능하다. 친구 관계와 클라이언트 준비를 별개로 보여 준다. 에이전트가 없다는 이유로 빈 발신 선택기를 표시하거나 친구 요청을 막지 않는다. 대화 시작 시에는 필요한 에이전트 등록·연결로 안내한다. 등록만 된 에이전트와 실제 수신 준비가 된 클라이언트를 혼동하지 않는다.

| 상태 | 표시와 허용 행동 | 금지·경계 |
|---|---|---|
| 요청 제출 | ‘요청을 보냈습니다. 가능한 요청은 상대가 확인할 수 있습니다.’ | 유효/없는/차단/상대 수신 한도 여부로 존재를 구분하지 않는다. 성공한 친구라고 표시하지 않는다. |
| 받은 대기 | 요청자 이름, 연결 범위, 절대 만료 시각; 수락·거절. 거절 앞 안내: ‘거절하면 요청한 사람의 기록에 거절로 표시됩니다. 알리지 않으려면 응답하지 않아도 기한이 지나면 요청이 끝납니다.’ | 수신 당사자만 결정한다. 수락 전에 상대 에이전트 목록을 보여주지 않는다. |
| 보낸 대기 | ‘보낸 친구 요청’, 만료 시각; 요청 취소 | 상대 이름·목록·존재 확인 결과를 표시하지 않는다. 반복 요청이 24h 기한을 늘리지 않는다. |
| 친구 | 친구 이름과 활성 에이전트; 대화하기 | 친구의 친구·이메일·키·credential은 비공개다. |
| 거절·취소·만료·해제 | 종료 상태와 ‘새 친구 요청과 수락이 필요합니다’. 요청자에게도 ‘거절’을 보인다(받은 사람의 명시 행동). 응답 없는 만료는 없는 코드의 만료와 같은 모양이다 | 자동 재요청·재수락·옛 세대 재사용이 없다. 종료별 의미를 합치지 않는다. |
| 차단 | 본인 차단 관리에서만 해제 | 상대에게 차단 여부를 공개하지 않는다. 해제만으로 친구가 되지 않는다. |
| 에이전트 0개 | 필요한 쪽의 등록/연결 안내 또는 친구 목록 복귀 | 빈 선택기·작동할 수 없는 보내기 버튼을 두지 않는다. |

완료 조건 U4-A: 서로 다른 회원 A/B와 제삼자 C, 같은 소유자 둘, legacy 회원을 구분한다. 반복/반대 요청·중복 수락·24h 경합·구세대 결정·차단·코드 교체를 검증한다. GET·방문·뒤로가기만으로 관계가 생성/수락되지 않는다. 미수락·철회 관계로 전달할 수 없다. 새 활성 에이전트는 이미 수락한 친구 범위에 포함되며 새 친구 요청을 요구하지 않는다. 기존 회원의 자기 연결 동의와 기존 pair 범위는 조용히 확대하지 않는다.

## U6 — 요청 상태 조회와 입력 복구

화면 제목과 진입 링크는 ‘요청 상태 조회’로 바꾼다. 설명은 ‘보낸 요청이나 답장의 ID로 전달 상태를 확인합니다. 현재 온라인 상태를 확인하는 기능은 아닙니다.’다. 내 에이전트 상세와 기존 관리 화면에서 같은 조회 화면으로 접근한다. 주 메뉴 세 개를 늘리지 않는다.

첫 화면과 성공·오류 화면 모두 같은 편집 폼을 제공한다. 라벨은 ‘내 에이전트’, ‘요청 ID 또는 답장 ID’, 버튼은 ‘상태 확인’이다. 선택기는 U2 이름 체계를 따른다. 요청 ID는 사용자가 받은 값을 붙여 넣게 한다. 합성 UUID 예시는 형식 설명일 뿐 실제 조회 성공 예시라고 표시하지 않는다.

| 결과 | 유지할 입력·안내 | 다음 행동 |
|---|---|---|
| 빈/형식 오류 | 같은 선택과 안전한 원입력, 필드 오류 | 오류 필드로 이동하고 수정 후 조회 |
| 없는/타인/접근 불가/보존 종료 | 동일한 ‘이 요청의 상태를 확인할 수 없습니다. 내 에이전트와 요청 ID를 확인하세요.’ | 같은 폼에서 수정; 존재·소유자·차단 여부를 설명하지 않음 |
| 권한 있는 만료 receipt가 아직 보존됨 | 선택/ID 유지, ‘전달 기한 만료’와 실제 기한 | 현재 연결·친구를 확인하고 필요하면 별도 승인으로 새 메시지 작성 |
| 429 | 입력 유지, 서버가 제공한 재시도 가능 시각 | 자동 polling 없이 수동 조회 |
| 일시 장애 | 입력 유지, 확인 실패 표시 | 잠시 뒤 같은 조회; 자동 발송 없음 |
| 세션 만료 | 재로그인 안내, 승인된 같은 회원의 조회 문맥만 복원 | 다른 계정으로 로그인하면 이전 선택/ID를 복원하지 않음 |

새로고침·뒤로가기·재조회·‘조회 입력으로 돌아가기’는 해당 폼 위치와 선택/ID를 복원한다. 보존 범위는 현재 인증된 조회 흐름이다. 조회 이력의 장기 저장·계정 간 공유는 추가하지 않는다. 원문·키·credential·세션 값은 URL·복귀 파라미터·화면·로그에 넣지 않는다. 요청 ID도 진단 수집에 무조건 기록하지 않는다. 구현의 저장·복귀 방식과 길이 제한은 DEV가 정하되 오입력은 이스케이프하고 과대 입력은 안전 거절한다.

성공 결과는 ‘전달’, ‘처리’, ‘관련 답장’을 분리한다. 대기/수신 확인 중은 ACK 전이다. 전달됨은 보관·ACK 성공이며 읽음·실행·답장 완료가 아니다. 조회 버튼은 송신하지 않는다. 키 재발급과 멱등키를 혼동시키는 ‘새 key로 송신’ 문구는 ‘새 메시지로 보내기’로 바꾼다. 기술 상세에서만 원래 상태값과 멱등 규칙을 설명한다.

완료 조건 U6-A: 잘못된/없는/타인/보존 종료 ID의 비공개 비노출, 권한 있는 만료 ID, 429·503·세션 만료, 새로고침·뒤로가기·반복조회·키보드 수정을 같은 격리 fixture에서 확인한다. 선택한 내 에이전트가 철회되면 다른 에이전트로 조용히 바꾸지 않고 다시 선택하게 한다.

## U5 — 사람이 판단하는 승인 요약

빈 목록은 ‘승인 요청이 없습니다. 사람의 확인이 필요한 요청이 여기에 표시됩니다. 친구 수락이나 메시지 수신만으로 요청이 승인되지는 않습니다.’로 설명한다. 목록에는 요청 주체/상대의 허용된 이름·구분값, 요청 유형, 만료 시각, 현재 상태, ‘요청 검토’를 둔다. 원요청 ID는 기술 상세로 옮긴다.

상세의 읽기 순서는 ‘누가 누구에게’, ‘요청한 내용’, ‘승인하면 허용되는 범위’, ‘기한·상태’, 행동, 기술 상세다. 요약은 현재 검증된 요청 바인딩과 허용된 구조화 필드만 사용한다. 표시 이름은 읽기 보조이며 서명·ID·digest·관계 세대 결속을 대신하지 않는다. `hint`·대화 text·외부 자유문을 승인 범위로 승격하거나 AI로 요약하지 않는다.

각 지원 요청 유형에 대해 DEV는 검증된 필드와 사용자 문구의 대응표를 남긴다. 일정 요청의 시간 범위 같은 구조화 필드도 실제 schema에 있을 때만 보인다. 없는 목적·수신자·권한을 추측하지 않는다. 이름 조회권한이 없으면 원래 허용된 ID와 안전 fallback을 쓴다. 자유문은 ‘요청자가 적은 내용’으로 분리하고 실행/링크 자동 열기를 하지 않는다.

승인 직전 고정 설명은 ‘승인은 이 요청의 인간 게이트만 통과시킵니다. 정보 공개나 일정 실행을 허용하지 않습니다.’다. 기존 비활성 정책을 실행 지원으로 바꾸지 않는다. 버튼은 ‘이 요청 승인’, ‘거절’이다. 원문 JSON·내부 ID·정책 식별자는 ‘기술 상세’, hint는 ‘참고 문구 — 승인 근거 아님’에 둔다. 요약에서 생략한 검증 필드는 기술 상세에서 확인할 수 있어야 한다.

만료·처리됨·현재 처리 상태를 다시 확인해야 하는 화면은 중복 행동을 유도하지 않는다. 원문 부재·서명/바인딩 불일치·미지원 유형이면 ‘승인할 내용을 확인할 수 없습니다’와 안전한 복귀만 제공한다. 버튼을 숨기는 것과 별개로 서버의 현재 owner·키·세대·기한 재검사를 유지한다. 낡은 화면의 제출은 새 요청에 적용되지 않는다.

완료 조건 U5-A: 검증된 요청의 요약/원문 일치, 이름 변경 뒤 같은 원요청 식별, 승인/거절/만료/재접근/중복 클릭을 확인한다. 악성 hint·HTML·바뀐 digest·다른 owner·원문 부재·관계 철회에서 요약으로 권한이 넓어지지 않는다. UI 시험을 위해 실제 외부 업무 실행을 활성화하지 않는다.

## U7 — 보조 화면의 위치와 접근성

회원 화면은 ‘대화 / 친구 / 내 에이전트’를 유지한다. 헤더의 기존 ‘내 계정’ 진입을 ‘설정’으로 표시하고 같은 계정 공간에서 이름·코드·언어·보안을 찾게 한다. 독립 승인/조회/동의 화면은 주 메뉴를 억지로 현재 위치로 표시하지 않는다. 고유 title·h1·header·main·본문 건너뛰기와 ‘요청 상태 조회’, ‘요청 승인’, ‘클라이언트 연결’ 같은 위치명을 제공한다.

각 화면에는 정확한 내부 복귀 링크를 둔다. 조회는 입력 폼, 승인은 승인 목록, 키 연결은 내 에이전트의 해당 관리 위치로 돌아간다. 진입 문맥이 없거나 권한이 사라지면 해당 안전 목록으로 복귀한다. 임의 외부 return URL을 받지 않는다. Remote 승인 뒤의 앱 복귀만 기존 검증된 redirect 계약을 사용한다. ‘앱으로 돌아가는 중’은 키 교환·연결 완료를 뜻하지 않는다. 자동 복귀가 실패하면 검증된 앱 링크와 만료 시 앱에서 다시 시작하는 안내를 제공한다.

기존 legacy의 한 페이지 앵커 목록은 ‘이 화면에서 찾기’로 구분한다. 스크롤 위치를 추측해 `aria-current`를 거짓 표시하지 않는다. 독립 페이지는 실제 현재 페이지만 `aria-current=page`, 연결 단계는 확인된 단계만 `aria-current=step`이다. 현재 기능은 시각 선택선과 텍스트로도 구분한다.

오류 뒤에는 요약과 해당 입력으로 도달할 수 있고 입력값이 남아 있어야 한다. 결과 안내는 status, 오류는 alert를 사용한다. 배경 갱신이 포커스를 빼앗지 않는다. 반복되는 재확인·이름 저장·철회 버튼의 접근성 이름에는 대상과 구분값을 넣는다. 동의·취소를 색만으로 구별하지 않는다.

완료 조건 U7-A: 1440·390·320px, 브라우저 실제 200% 확대, Tab/Shift+Tab/Enter/Space, 스크린리더의 title·landmark·현재 위치·오류·결과를 확인한다. 최소 44px 동작, 보이는 focus, 본문 대비 4.5:1·입력/focus 3:1을 유지한다. 긴 한영 이름·ID·URL과 확대에서 페이지 가로 넘침·잘림·키보드 함정이 없다. 주 브라우저 외 한 브라우저에서 복귀·폼·details를 짧게 확인한다. 실행하지 못한 조합은 not_run으로 남기고 전체 접근성 완료라고 보고하지 않는다.

## U3 — 설정과 언어 저장

설정은 기존 내 계정 공간을 확장한다. 순서는 ‘내 이름’, ‘내 친구 코드’, ‘언어’, ‘로그인과 보안’이다. 언어 선택은 ‘한국어 / English’ 두 개와 ‘언어 저장 / Save language’를 제공한다. 선택만으로 폼 제출이나 재로그인을 실행하지 않는다. 저장 성공 후 선택한 언어로 같은 설정 위치를 보여 준다. 실패하면 이전 저장값과 실패 사실을 구분하고 사용자가 선택한 값을 유지한다.

로그인 회원의 명시적 선택은 계정에 저장한다. 새로고침·다른 화면·로그아웃 후 재로그인·다른 브라우저의 같은 계정에서 유지한다. 같은 브라우저에서 다른 계정에 로그인하면 그 계정의 선호를 사용한다. 새 선택은 다음 화면 요청부터 적용하며 다른 열린 탭을 강제로 다시 로드하지 않는다.

| 상황 | 사용할 언어 |
|---|---|
| 로그인 회원에 유효한 저장값 있음 | 계정의 `ko` 또는 `en` |
| 회원 저장값과 명시적 비로그인 선호 모두 없음 | 한국어 |
| 비로그인 사용자가 명시적으로 언어 선택 | 해당 브라우저의 다음 방문에도 유지; 저장이 차단되면 현재 응답만 적용하고 한계를 안내 |
| 비로그인 선호를 가진 첫 로그인, 회원 저장값 없음 | 비로그인 선택을 화면에 적용하되 계정 저장은 설정의 명시적 저장으로 확정 |
| 계정 A 로그아웃 후 B 로그인 | B 저장값 우선. A의 계정 선호를 익명/다른 회원 선호로 복사하지 않음 |
| 알 수 없거나 손상된 locale | 한국어 fallback; 내부 오류나 임의 번역을 노출하지 않음 |

브라우저 언어 자동 감지는 이번 범위에서 생략한다. 비로그인 언어 진입은 기존 공개 페이지·로그인·동의 화면에 작은 ‘한국어 / English’ 링크로 제공한다. 공개 페이지의 정보 구조·설치 사실·토큰은 바꾸지 않는다. 영어판은 같은 의미와 기능이며 로그인·설치 성공을 새로 약속하지 않는다. 현재 공개 CSS 선행 과제가 수락된 뒤 별도 DEV 과제에서 적용한다.

번역 범위는 공개/로그인/이름/대화/친구/내 에이전트/설정/legacy/receipt/승인/local 연결/remote 동의·복귀의 사용자 문구다. 제목·메뉴·라벨·상태·빈 상태·오류·검증·접근성 이름·도움말을 포함한다. 프로토콜 ID·키·명령·사용자 이름·메시지·검증 원문 JSON은 번역하지 않는다. 외부 호스트 UI·Google 화면과 README 전체 번역은 이번 웹 UI 완료 범위에서 제외한다. 외부 한국어 문서 링크는 언어를 표시한다.

HTML `lang`는 실제 선택 언어와 일치한다. 날짜의 시간대는 두 언어 모두 기존 KST로 유지한다. 짧은 대화 시각은 기존 D04 의미를 번역한다. 정확한 기한에는 날짜·시각·KST(UTC+09:00)를 명시한다. 언어 전환으로 기한·정렬·프로토콜 timestamp가 바뀌지 않는다. 시간대 설정은 추가하지 않는다.

누락 번역은 한국어 원문으로 안전 fallback하고 해당 문구의 언어를 구분한다. 내부 번역 키나 빈 버튼은 표시하지 않는다. 런타임 fallback은 장애 보호다. 명시한 필수 화면에 누락 번역이 남으면 #3 완료가 아니다. 문구·상태의 관리 방식은 DEV가 정하며 새 번역 의존성 도입을 제품 요구로 강제하지 않는다.

완료 조건 U3-A: 한국어/English 저장·실패·새로고침·재로그인·새 브라우저·계정 교대·익명 저장 차단·잘못된 locale을 검증한다. 언어 전환이 친구 요청·발송·승인을 실행하거나 입력을 잃게 해서는 안 된다. 원문/ID/서명값 불변, 날짜의 동일 시각, `lang`·접근성 이름·누락 번역·긴 영문 배치를 확인한다. 계정 삭제·내보내기·새 보안 설정은 추가하지 않는다.

## U8 — 설치 경로, 상태와 재개

회원의 ‘내 에이전트’에서 발급 전에 ‘어디에서 사용할까요?’를 제공한다. 웹 사용·Grok Bot 로컬·Dots 원격·지원 확인이 필요한 호스트를 구분한다. 호스트·실행 위치·OS/버전·설치 권한을 확인할 수 있게 한다. 웹은 별도 설치가 필요 없지만 송신 대상과 권한은 필요하다. Local과 Cloud를 하나의 설치 명령으로 합치지 않는다.

원자료: [실계정 친구 대화](../evaluations/qa-reports/SAR-HUMAN-PEER-002-LIVE/report.md), [알림 관측](../evaluations/qa-reports/SAR-HUMAN-PEER-003-NOTIFY/report.md), [10-14 운영 보존](../evaluations/qa-reports/SAR-REFACTOR-002-OPS/report.md). 마지막 기록의 배포 제품은 `8a93e38e190f1b9e7b6bb183e578e410f5dd97c6`이며 새 실계정 송수신 검증은 아니다. 오래된 adapter 절의 ‘앱 미확인’과 뒤의 한정 실제 관측을 날짜 없이 하나로 합치지 않는다.

후속 검증표는 호스트별 제품/버전·OS·계정 권한·소스 SHA·패키지 검사·깨끗한 앱 설치·도구 검색·인증·이름 등록·친구 수락·왕복·재개·검증 날짜·근거를 각각 기록한다. 관측 당시 앱 버전이 없으면 ‘미기록’이다. 소스/패키지 PASS를 앱 설치 PASS로 채우지 않는다. ‘신규 설치 검증 완료’ 표시는 이 단계가 동일한 명시 환경에서 모두 통과한 호스트에만 허용한다.

### 한 흐름과 재방문

1. 사용 환경과 ‘처음 연결 / 기존 연결 계속’을 고른다. 기존 연결은 현재 agent/key를 먼저 확인한다.
2. 선택 경로의 준비물·권한·설치·도구 검색 기대 결과를 읽는다. 실행 내용은 현재 README와 연결한다.
3. 해당 호스트에서 연결을 시작한다. Local은 본인이 시작한 지문을 비교한다. Remote는 호스트에서 OAuth를 시작하고 서버 보관 범위를 확인한다.
4. 같은 설치 인스턴스의 이름과 agent를 확인한다. device/remote에서 새 agent를 만드는 경로 앞에 수동 agent 생성을 의무화하지 않는다.
5. 클라이언트 저장·키 등록을 확인한다. 친구에게 이름이 보이며 현재·향후 활성 agent 동의 범위가 적용됨을 설명한다.
6. 사람 친구 코드로 요청하고 상대가 수락한다. 기존 자기 연결 동의가 끝난 같은 소유자라면 친구 요청을 반복하지 않는다.
7. 사용자가 대상·비민감 본문을 명시 승인하면 확인 메시지를 보낼 수 있다. 전달·화면 수신·관련 답장 receipt를 각각 확인한다. 버튼을 눌렀다는 이유로 자동 시험 발송하지 않는다.

진행 표시는 서버가 확인한 상태만 완료로 올린다. 외부 설치나 도구 검색을 서비스가 관측하지 못하면 ‘앱에서 확인 필요’로 남긴다. 방문 이력이나 접기 열림을 설치 완료로 기록하지 않는다. 최소 재개는 해당 설치·agent·미완료 단계·다음 행동을 다시 찾는 기능이다. 새로운 범용 체크리스트 엔진은 요구하지 않는다.

| 관측 상태/실패 | 사용자 설명과 재개 | 보호 조건 |
|---|---|---|
| 미시작·도구 없음·권한/버전 문제 | 호스트 준비 단계와 필요한 권한으로 돌아감 | 미지원 경로에서 발급/설치 성공 버튼을 제공하지 않음 |

| 오프라인 추정·전달 만료·429 | 관측된 실패와 수신 앱/요청 조회 안내 | online 추측 금지, 자동 재발송·TTL 연장 금지 |

설치됨, 도구 검색 가능, 로그인/키 등록, 수신 프로세스, 친구 관계, queued, 전달됨, 화면 표시, 답장은 각각 다른 상태다. 현재 신뢰 가능한 온라인 신호가 없으면 ‘온라인’ 배지를 만들지 않는다. SSE/Events 구독과 ACK도 호스트 화면 성공을 대신하지 않는다. 재방문 후 모든 권한·기한을 다시 확인한다.

완료 조건 U8-A: 격리 local/remote fixture에서 생성·취소·만료·응답 유실·새로고침·재시작·중복 클릭·거절·rate limit의 상태 복구를 확인한다. 기존 agent/key·친구·Inbox를 보존한다. 실제 지원 완료는 별도 승인된 깨끗한 호스트 설치와 인증·친구·왕복 실증이 있어야 한다. 이번 설계나 합성 QA만으로 다섯 호스트를 지원 완료로 닫지 않는다.

## 화면 배치와 자기 비평

기존 D04의 canvas/ink/muted/accent/selected/edge 여섯 토큰, danger, 시스템 한글 글꼴, 간격·44px 제어·4px 모서리를 그대로 쓴다. 본문은 왼쪽 정렬이다. 화면마다 상태 카드·통계·배지·그라디언트·알약 버튼을 추가하지 않는다. 구현은 기존 Go template·네이티브 form/details를 재사용한다. 새 테마·폰트·이미지·프레임워크·JS를 요구하지 않는다.

첫 구상은 모든 화면에 일곱 단계 온보딩을 고정했다. 이미 연결한 회원에게 불필요하고 상태를 과장할 수 있다. 최종안은 해당 화면에서 현재 대상·오류·다음 행동만 먼저 보인다. 긴 설치 근거와 원문은 접되 승인 범위·실패 이유는 접지 않는다. 초기 handle/상대 미리보기 구상도 코드 존재를 누설하므로 제외했다.

```text
요청 상태 조회                       설정
내 에이전트 [이름 / 종류 / 구분값]     내 이름
요청 ID [입력한 값 유지]              내 친구 코드 [선택·복사]
[상태 확인]                          언어 [한국어 / English]
오류와 수정 방법                     [언어 저장]
전달 / 처리 / 관련 답장              로그인과 보안
기술 상세                            로그아웃과 키 철회의 차이

요청 승인                            내 에이전트의 연결 안내
주체와 상대                          사용할 곳 / 처음·기존 연결
검증된 요청 내용                     지원 근거와 확인 필요 항목
승인하면 허용되는 범위               현재 agent·설치·단계
기한·상태                            다음 행동 하나
[이 요청 승인] [거절]                상태 확인 / 취소
기술 상세 / 승인 목록                설치·복구 상세 / 내 에이전트
```

1440px은 기존 shell과 읽기 폭을 유지한다. 390·320px에서는 위 순서의 한 열이다. 입력·오류·버튼을 같은 흐름에 둔다. 두 언어의 긴 문구가 줄바꿈해도 승인 대상과 행동을 분리된 화면에 숨기지 않는다. 이 와이어프레임은 설계이며 렌더·시각 PASS 근거가 아니다.

## 순차 DEV·QA 인계와 완료 판정

coor가 CSS 선행 과제를 정리하고 인박스가 비면 아래 기능 단위로 정규 지시서를 작성한다. 현재 다른 역할 인박스에 쓰지 않는다. DEV는 기술 계획·API/구조·저장 방식·구현·자동 검사·기술 원천 갱신을 맡는다. 각 후보는 DEV 검사, tester 독립 동작 QA, designer 직접 시각 검수, 별도 고정 SHA 리뷰 뒤 coor가 통합한다. 다음 단위는 수락된 직전 통합 후보를 기준으로 한다.

#3은 원 이슈 P1을 유지한다. 마지막 순서는 낮은 중요도라는 뜻이 아니다. 앞 단위의 한국어 문구가 확정된 뒤 한 번 번역해 중복 작업을 줄인다. 중간 단위의 완료로 #3을 닫지 않는다. 공통 접근성은 각 단위에서 먼저 확인하고 마지막 후보에서 새 번역 영향만 재검증한다.

필수 `product-lint`·`product-test`와 보안·독립 리뷰는 lite에서도 유지한다. 자동 검사는 변경한 핵심 동작과 실패 경계에 맞춘다. 사소한 문구만 바꾸면 새 테스트를 만들지 않는다. 모든 새 실패를 과거 PASS로 대체하지 않는다. 고정 SHA·환경·동일 입력·명령 자신의 종료코드가 있는 기존 검사는 동일성을 확인한 범위만 재사용한다.

tester는 합성 A/B/C·legacy·local/remote fixture, loopback origin/포트·DB 식별자·허용 GET/명시 POST·독립 assertion·시간 예산을 기록한다. 운영·실메일·실상대·배포·삭제/이동은 금지한다. 시각 검수는 실제 후보의 조회 오류·승인 요약·친구 빈 상태·연결 실패·설정 두 언어 캡처를 사용한다. 정적 fixture와 실제 인증/DB 조작은 구분한다.

이 설계에서 D02/D04/D11 요구를 연결했지만 기존 원천·인덱스를 변경하지 않았다. 후속 DEV가 구현과 달라지는 기술·사용 안내를 갱신한다. D02/D04의 추가 반영은 coor가 designer 범위로 별도 전달한다. 공개 첫페이지 규칙의 의미나 사람 친구 동의 범위를 바꿀 필요가 생기면 제품 판단으로 되돌린다. 독립 리뷰·main 통합은 coor 책임이다.

완료 판정은 이슈별 U2–U8 수락 근거로 한다. #2는 이름 확장 적용과 handle 미도입 결정을 함께 기록한다. #4는 옛 요구를 현재 모델로 대체한 근거를 기록한다. #8은 미지원 세 호스트의 정직한 안내 완료와 실제 설치 지원 완료를 분리한다. 외부 GitHub 상태/댓글은 이 작업에서 변경하지 않는다.
