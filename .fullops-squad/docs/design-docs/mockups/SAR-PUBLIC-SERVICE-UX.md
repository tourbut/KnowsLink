# 일반 이메일 서비스 화면 수락 기준

## 목적과 책임

[일반 서비스 D02](../../planning/product-specs/SAR-PUBLIC-SERVICE.md)의 PS-01–14를 사용자가 확인할 수 있는 화면 동작으로 정의한다. designer는 제품 UX와 직접 시각 검수를 맡는다. DEV는 기존 Go UI 방식과 기술 구조를 정하고 구현한다. 디자인 문서 완료는 실제 UI PASS가 아니다.

## 최소 화면과 다음 동작

| 화면 | 필수 정보·동작 | 시각 수락 항목 |
|---|---|---|
| 시작·가입/로그인 | 이메일 확인 시작, 확인 수단 안내, 재발송 가능 시점, 안전한 오류 | UX-01: 일반 사용자가 관리 오너 인증이나 SSH 없이 시작한다. 가입 여부를 노출하지 않는다. 확인 완료 전 보호 화면에 들어가지 않는다. |
| 확인 대기·실패 | 만료·오답·발송 실패·제한 안내, 재시도 동작 | UX-02: 발송 성공과 신원 확인 완료를 구분한다. 인증코드를 로그·캡처에 남기지 않는다. |
| 자기 owner 홈 | 마스킹한 자기 신원, 자기 agent 목록, 새 연결, 관계, 로그아웃·전체 로그아웃·계정 비활성화 | UX-03: 운영 관리 메뉴와 타 회원 목록이 없다. 재로그인 후 같은 자기 목록을 보인다. 일반 세션 종료와 agent 연결 철회를 구분한다. |
| agent 연결·키 | 지원 클라이언트, 설치/연결 안내, 대상 agent·공개키 지문·권한·기한, 확인/취소, 회전/철회 | UX-04: 개인키·관리자 token·서버 경로 복사를 요구하지 않는다. 자기 클라이언트 안내는 실행 위치를 명시한다. 연결 대기/완료/만료/미지원/철회를 문구로 표시한다. |
| 관계 | 상대 agent 식별자, 발신/수신 초대, 수락·거절·철회, 현재 상태 | UX-05: 서비스 가입 초대와 관계 초대를 혼동하지 않는다. pending 수락 전 메시지 전송을 활성화하지 않는다. 상대 이메일을 표시하지 않는다. |
| 연결 확인·receipt | 선택한 agent, 사용자 명시 송신, 요청 ID·관련 답장 ID, 현재 전달/실패 상태·TTL, 수동 수신 확인 안내 | UX-06: queued·실제 수신·답장 수신을 구분한다. 자동 wake 미지원 시 숨기지 않는다. 만료·오프라인·제한·철회에는 가능한 복구 동작을 보인다. |
| 기존 human-gate | 검증된 typed body·정책·발신/대상·만료, approve/deny, 원문 부재와 권한 상태 | UX-07: hint와 본문이 달라도 본문이 판단 근거다. 원문 부재·만료·철회에 승인 버튼이 활성화되지 않는다. |

## UX-05 반복 초대와 재초대

[PS-07 상세 규칙](../../planning/product-specs/SAR-PUBLIC-SERVICE.md#ps-07-관계-초대의-반복과-재수락)을 적용한다. pending 화면은 발신/수신 방향·기한과 수신 owner의 수락/거절을 구분한다. 반복 제출 뒤에는 기존 초대가 대기 중임을 안내한다. 기한을 갱신하거나 반복 제출을 수락으로 표시하지 않는다. active에서는 이미 연결된 현재 관계를 안내한다.

거절·만료·철회 결과는 연결 종료와 메시지 불가를 안내한다. 재초대가 가능한 경우 사용자가 직접 새 초대를 선택할 수 있게 한다. 새 pending에서는 상대의 새 수락을 기다린다고 표시한다. 거절·철회가 영구 차단이라는 문구나 자동 재연결·자동 재시도는 제공하지 않는다. 별도 과거 초대 목록·장기 타임라인은 요구하지 않는다.

한도 초과·권한 거부·만료된 결정의 오류는 성공으로 표시하지 않는다. 현재 관계 확인·홈 복귀 또는 제한 해제 후 수동 재시도 중 실제 가능한 다음 동작을 제공한다. 상대 이메일·타 회원 존재·기술 세대값을 사용자에게 추가 노출하지 않는다. 화면에 새 세대값 표시를 완료 조건으로 요구하지 않는다.

이번 규칙 기록은 원본 [AGENTS 직접 검수](SAR-PUBLIC-AGENTS-001-UI.md)의 FAIL/보류를 변경하지 않는다. DEV 수정의 고정 후보에서 designer가 관계 상태·반복 결과·재초대 뒤 대기·오류 뒤 다음 동작을 영향 범위만 직접 재검수한다.

## UX-04/05 기록 포화와 agent 교체

[D02의 기록 보호 조건](../../planning/product-specs/SAR-PUBLIC-SERVICE.md#ps-050611-기록-보호에-따른-교체와-목록-정리)을 따른다. 키 기록 포화는 “이 에이전트에는 새 키를 연결할 수 없습니다. 새 에이전트로 연결하고 상대와 관계를 다시 수락하세요”와 같은 상태·다음 동작을 제공한다. 기존 agent 관리와 새 agent 생성으로 이동할 수 있게 한다. 활성/기록 한도로 생성할 수 없는 경우 실제 제한을 추가 안내한다. 자동 교체·키 삭제·관계 승계는 제공하지 않는다.

agent 기록 포화는 새 생성 실패와 “철회된 에이전트 기록의 보존·정리 뒤 다시 시도하세요”를 안내한다. 철회 기록은 최소 24h 보존하며 실제 정리 후 공간을 확인해야 한다. 사용자에게 기술 보호값을 상품 quota로 표시하지 않는다. 일반 회원이 정리 완료 여부를 확인할 수 있도록 자기 홈 새로고침·관리 복귀·가능 시 수동 재시도를 제공한다. 정리 budget까지 제한되면 기존 제한과 재시도 안내를 제공한다.

기존 agent 철회 전에는 키·관계 종료와 기존 agent 복구 불가를 알려야 한다. 별도 확인 화면이나 새 모달을 요구하지 않는다. 새 agent는 별도 연결 상태와 관계 수락 대기를 표시한다. 연결 완료를 상대 관계 완료로 표시하지 않는다. 보존 중 철회 agent는 철회 상태를 보인다. 최소 24h 뒤 실제 정리 시 목록에서 사라질 수 있음을 안내한다. 정확한 삭제 타이머·백업 영구 삭제·새 권한 복구를 약속하지 않는다.

designer는 고정 후보에서 키/agent 기록 포화의 오류와 다음 동작·새 연결과 새 관계 대기·철회 안내·정리 전후 목록을 직접 확인한다. DEV 자동 검사나 이번 제품 문서를 시각 PASS로 표시하지 않는다.

## 화면 방향

기존 화면의 정보 구조를 유지하고 제목·상태·다음 동작을 일관되게 배치한다. 로그인·연결 확인·관계 결정에서 키보드 이동과 읽을 수 있는 오류 문구를 제공한다. 상태는 색만으로 구분하지 않는다. 긴 식별자는 복사와 읽기를 지원한다. 인증 입력은 개인 비공개 흐름에서 처리한다.

채팅 버블·자유 대화 composer·장기 메시지 타임라인을 추가하지 않는다. 무조건 성공 배너·queued를 수신 완료로 표시하는 문구·인증 실패 상태의 활성 승인 버튼을 쓰지 않는다. 관리 오너의 Basic 인증 절차를 일반 사용자 가입 안내로 사용하지 않는다. 별도 장식 에셋과 새 frontend는 요구하지 않는다.

## 직접 검수와 증거

coor가 안정된 후보 SHA·운영 환경·일반 QA 계정 사용 권한을 제공한다. designer는 UX-01–07을 같은 후보에서 직접 확인한다. 사용자도 일반 이메일로 실제 가입/로그인·로그아웃·재로그인을 확인한다. TESTER 자동 결과와 이 사람 확인은 별도로 기록한다. UX-08은 일반 서비스 수락 뒤 새 과제에서 두 플랫폼의 실제 일반 온보딩·명시적 관계 수락·노우→다닷 수신·다닷→노우 회신 ID와 앱 도구 상태를 확인한다. 두 다른 이메일을 사용자에게 요구하지 않는다.

필요한 캡처는 확인 대기/실패, 자기 홈, 연결 상태, 관계 수락/철회, receipt 실패/답장, gate 만료/철회다. 이메일·코드·연결 수단·key/token은 캡처 전에 가린다. 기한 변화가 정지 캡처로 판정되지 않을 때만 짧은 영상을 만든다. 기존 gate 캡처는 관련 의존성 동일성을 확인했을 때 원래 SHA의 증거로 재사용한다. 새 이메일 인증과 연결 화면은 기존 합성 캡처로 대체하지 않는다.
