# Claude Code·Codex 자동 설정의 제품 규칙 — SAR-AUTOSETUP-001

## 상태와 근거

이 문서는 [intent SAR-AUTOSETUP-001](../intents/SAR-AUTOSETUP-001.md)의 요구사항(D02)이다. intent가 승인 전이므로 이 문서도 확정 전이다. intent의 열린 질문 Q1–Q6 답에 따라 표시한 규칙을 고친다. 추천안을 기준으로 썼고 해당 규칙에 `(Qn)`을 붙였다.

기준 커밋은 main `cfdd642b3dfe5d8852df8a869d77a3a2499a5a02`다. 이 문서는 다음 확정 규칙을 바꾸지 않는다: LG-04, HP-10, SP-01–12, D023–D030. 기술 계획(설치기 언어·배포 위치·호스트 CLI 사용법)은 DEV가 정한다.

용어:

- **설치기**: 회원 화면이 보여 주는 명령으로 실행되는 프로그램이다.
- **설치**: 한 컴퓨터·한 호스트의 KnowsLink 플러그인 폴더와 그 폴더의 agent 폴더(`<설치>-private`)다.
- **설치 계획**: 설치기가 바꾸기 전에 보이는 변경 목록이다.
- **호스트**: Claude Code 또는 Codex CLI다.

## 제품 규칙

| ID | 규칙 | 지켜야 할 조건 |
|---|---|---|
| AS-01 한 명령 | 호스트마다 명령 하나로 신규 설치와 기존 갱신을 모두 시작한다(Q1). | 사용자는 저장소 clone, 빌드, Node 버전 선택, 절대 경로 입력, 환경 변수 설정, 설정 파일 편집을 하지 않는다. 명령에는 고정 버전이 있다. 설치기는 내려받은 내용물의 checksum이 맞지 않으면 아무것도 쓰지 않고 멈춘다. |
| AS-02 설치 계획 먼저 | 설치기는 바꾸기 전에 설치 계획을 보이고 사용자의 동의를 받는다. | 계획에는 설치 폴더, agent 폴더, 바꿀 호스트 설정 파일과 항목 이름, 호스트·버전·OS 확인 결과, 신규인지 갱신인지가 있다. 동의 전에는 파일을 쓰지 않는다. 거절하면 바뀐 것이 없다고 알리고 끝난다. |
| AS-03 자동으로 하는 일 | 동의 뒤 설치기가 사람 입력 없이 한다. | 내려받기·검증, 실행에 필요한 Node 준비, 새 설치 폴더 결정, 절대 경로가 들어간 MCP 설정, 호스트 등록(Q3), 등록 확인, 갱신 때 이전 설치 보존. 설치 폴더는 기본 위치에 만들고 이미 있으면 겹치지 않는 새 이름을 쓴다. |
| AS-04 사람이 반드시 하는 일 | 다음은 자동화하지 않는다. | 설치 계획 동의(AS-02), Google 로그인·지문 비교·에이전트 이름·연결 동의, 세션 연결(Claude Code `/knowslink-session on`, Codex `knowslink_session` `on`과 4자리 코드), 발송마다의 승인(HP-10, SP-05·06), 친구 요청·수락, 검증 안 된 버전에서 계속할지 선택(AS-09). |
| AS-05 Google 연결 | 신규 설치는 설치기가 등록 직후 Google 연결을 시작한다(Q2). | 설치기는 연결 링크를 연다. 열지 못하면 링크를 출력한다. 터미널에 지문을 보이고 사용자가 브라우저의 지문과 비교하라고 안내한다. 다른 사람이 보낸 링크는 승인하지 말라고 안내한다. 키는 그 컴퓨터의 agent 폴더에만 저장된다. 저장 확인 전에는 '연결됨'이라고 쓰지 않는다. |
| AS-06 자격 경계 | 설치기는 다른 설치의 자격을 읽거나 옮기지 않는다. | 다른 설치·Grok·Dots·다른 호스트의 키와 credential, 호스트 로그인·인증 파일을 읽거나 복사하지 않는다. 호스트 설정에서는 KnowsLink 항목만 추가·교체한다. 다른 MCP 항목·승인 모드·모델 설정을 바꾸지 않는다. 토큰·키를 URL·클립보드·로그에 남기지 않는다. |
| AS-07 호스트별 agent | 같은 컴퓨터에서 Claude Code와 Codex를 함께 쓰면 호스트마다 별도 설치와 agent를 만든다. | 한 agent는 한 세션만 받는다(SP-02). 설치기는 다른 호스트의 agent를 재사용하자고 제안하지 않는다. |
| AS-08 세션 연결은 따로 | 설치 완료는 세션 연결이 아니다(SP-01). | 설치기의 마지막 화면은 '설치와 키 저장 완료'와 세션 연결 명령을 보인다. 호스트 재시작이 필요하면 먼저 알린다. Codex는 승인 모드를 확인해 YOLO면 '이 설정에서는 연결할 수 없습니다'와 바꾸는 방법을 안내한다. 설치기는 승인 모드를 바꾸지 않는다. |
| AS-09 버전·OS 확인 | 설치기는 호스트 버전과 OS를 확인한다. | 범위 표의 버전·OS면 그대로 진행한다. 호스트가 없거나 실행할 수 없으면 바꾸기 전에 멈춘다. 다른 버전·OS면 '검증하지 않은 환경'을 보이고 사용자가 동의할 때만 계속한다(Q5). 이 경우 완료 화면에 '시험 환경 확인' 문구를 쓰지 않는다. macOS·Linux는 Q4 결정 전까지 지원 문구에 쓰지 않는다. |
| AS-10 기존 갱신 | 같은 컴퓨터·같은 호스트에 설치가 있으면 갱신으로 처리한다. | agent 폴더(키·agent 정보·Inbox)를 읽지도 바꾸지도 않는다. agent ID·키 지문·친구 관계가 같다. Google 연결과 이름 단계를 건너뛴다. 새 내용물이 검증될 때까지 이전 설치를 그대로 쓴다. 설치가 여러 개면 목록을 보이고 사용자가 하나를 고른다. 어느 것인지 확실하지 않으면 멈추고 '확인 필요'를 보인다. 갱신 대신 새 agent를 만들려면 사용자가 명시적으로 '새 에이전트로 설치'를 고른다. |
| AS-11 실패와 다시 실행 | 실패하면 실패 단계·이미 바뀐 것·다음 행동을 보인다. | 같은 명령을 다시 실행하면 마친 단계를 건너뛰고 이어서 진행한다. 다시 실행해도 같은 설치에 agent가 하나 더 생기지 않는다. 만료·취소한 Google 연결 시도는 재사용하지 않고 새 시도를 시작한다. 실패 뒤 자동 재시도·자동 정리는 하지 않는다. 사용자가 다시 실행한다. |
| AS-12 출력 언어와 기록 | 설치기 출력은 회원 화면 언어(KO/EN)를 따른다. | 명령에 언어 값을 담는다. 실패 출력에는 단계 ID(F-xx)를 함께 쓴다. 설치기는 설치 폴더에 설치 기록(버전·시각·단계 결과)을 남긴다. 키·토큰은 기록하지 않는다. |
| AS-13 제거 안내 | 이번에는 제거 명령을 만들지 않는다. | 완료 화면과 설치 기록에 설치 폴더·호스트 설정 항목 위치와 키 철회 방법(웹 '연결 관리')을 쓴다. |

## 수락 기준

각 수락 기준은 intent 성공 기준에 연결된다. 측정 환경은 intent `성공 기준`의 환경이다.

| ID | 수락 기준 | 성공 기준 | 증명 방법 |
|---|---|---|---|
| AC-01 | 신규 설치 N1–N8에서 사람 행동이 AS-04 목록과 명령 실행 1개, 필요할 때 호스트 재시작 1개뿐이다. 절대 경로·환경 변수·설정 파일 편집 입력이 0개다. | S1, S2 | tester가 호스트별 행동을 순서대로 기록한 표 |

| AC-03 | Codex에서 `CODEX_HOME`·marketplace·plugin add 수동 명령 없이 `knowslink_session` `on`이 동작하고 첫 발송이 4자리 코드 승인으로 한 번 보내진다. | S2 | 상대 수신 1건과 receipt |
| AC-04 | 명령 실행부터 N7 세션 연결까지 10분 이하다. | S3 | 호스트별 측정 1회의 시작·끝 시각 |
